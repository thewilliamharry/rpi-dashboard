<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI → recovery service | A local operator selects a destructive restore operation. |
| verified backup catalog → live database | Cataloged recovery data may replace the application source of truth. |
| Compose service topology → shared volume | Web, worker, and recovery must not write the same database concurrently. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-21 | Tampering | backup selection | high | mitigate | Opaque catalog IDs only; reject paths, symlinks, escapes, missing entries, unsupported fingerprints, and failed integrity. |
| T-01-22 | Tampering / Denial of service | atomic restore | high | mitigate | Shared lock, stale-worker requirement, same-filesystem staging, fsync, integrity recheck, atomic replace, and interruption tests. |
| T-01-23 | Elevation of privilege | recovery container | high | mitigate | Non-root UID 10001, no network, read-only root, dropped capabilities, no-new-privileges, and only `/data` mounted writable. |
| T-01-24 | Repudiation | restore result | medium | mitigate | Emit catalog ID, timestamp, fingerprint, and completion state without sensitive row data. |
| T-01-25 | Information disclosure | recovery CLI errors | low | accept | Safe local-LAN operational messages disclose only fixed `/data` concepts and catalog IDs; raw rows/exceptions remain redacted. |
</threat_model>
