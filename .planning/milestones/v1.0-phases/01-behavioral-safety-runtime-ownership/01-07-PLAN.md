<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| configured URL → host-networked HTTP/Chromium | Operator/configured targets can reach Pi/LAN/web destinations. |
| DNS/redirect → next connection | Name resolution and redirect data can change destination after initial validation. |
| LAN service TLS exception → webhook | A deliberate local exception must not cross into external alert delivery. |
| browser mutation → saved target/queued work | Local requests can persist URLs that the worker later fetches. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-31 | Tampering / Information disclosure | target and DNS validation | high | mitigate | Purpose allowlists, full URL parsing, every A/AAAA result validation, and pre-connection checks. |
| T-01-32 | Tampering / Information disclosure | redirects | high | mitigate | Disable automatic redirects; re-plan each service hop; cap at five; reject webhook redirects. |
| T-01-33 | Information disclosure | TLS posture | high | mitigate | Immutable per-request TLS plan; LAN exception only for eligible service purposes; strict verified webhook. |
| T-01-34 | Information disclosure / Denial of service | Playwright subresources | high | mitigate | Route every request type through policy and abort before access; keep deadlines/cleanup. |
| T-01-35 | Spoofing / Tampering | mutation routes | high | mitigate | Host, same-origin, and UI-header checks precede planning, persistence, and enqueue; overlap tests prove isolation. |
| T-01-36 | Information disclosure | policy/webhook errors | medium | mitigate | Stable reason classes and redacted persistence/UI mapping omit raw destinations, addresses, certificates, bodies, and stacks. |
</threat_model>
