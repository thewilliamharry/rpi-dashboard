<interfaces>
Existing entrypoints to preserve:
- `dashboard.app.get_db() -> sqlite3.Connection` is used by compatibility routes and worker operations.
- `beacon.db.connect_db(settings_or_path) -> sqlite3.Connection` underlies explicit transaction contexts.
- `beacon.queues._connect(db_path)` opens every owner/scan/preview state-machine connection.
- `beacon.migrations.run_migrations(settings, ...)` already owns `/data/.beacon-upgrade.lock`.

New contract:
- The sibling lock file `.beacon-maintenance.lock` is independent of the database inode being replaced.
- Ordinary connections hold `LOCK_SH` until `close()`; migration/restore holds `LOCK_EX` for the full maintenance interval.
- All code that needs both locks takes the upgrade lock first and the maintenance lock second.
</interfaces>
</context>
