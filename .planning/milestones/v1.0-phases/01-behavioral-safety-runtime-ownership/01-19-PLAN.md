<interfaces>
Existing contracts to preserve:
- `WorkerOperations` injects `prepare_database`, recovery/monitoring operations, browser shutdown, and `acquire_worker_lease`/`renew_worker_lease`/`release_worker_lease`; only `dashboard/worker.py` binds legacy compatibility operations.
- `queues.acquire_worker_lease(db_path, worker_id)` creates the authoritative SQLite `worker_owner`; `release_worker_lease` deletes only the matching owner and raises `queues.LeaseLost` when ownership is absent or belongs to a successor.
- `run_worker()` performs database preparation before lease acquisition, then recovery, initial heartbeat, initial metrics, scheduler construction, signal registration, and `scheduler.start()`.
- `stop_worker()` is the SIGTERM/SIGINT callback. Today it shuts down the browser, releases immediately, and asks the scheduler to stop; `run_worker()` only shuts down the browser in its final block.

Lifecycle contract introduced by this plan:
- `prepare_database` and `LeaseHeld` remain outside post-acquisition cleanup. After successful acquisition, `lease_acquired=True` activates one outer finally covering every subsequent operation and scheduler outcome.
- `_finalize_worker_lifecycle(services, worker_id)` uses nested cleanup so browser-shutdown failure cannot skip lease release, release failure cannot skip global reset, and only `queues.LeaseLost` is suppressed.
- `stop_worker()` requests scheduler shutdown but never transfers durable ownership itself. Final release occurs only after `scheduler.start()` returns/unwinds, closing the overlap window.
- Final cleanup sets `scheduler`, `_active_services`, and `_active_worker_id` to `None` and `_worker_started` to `False` on all paths, including LeaseLost and non-LeaseLost cleanup errors.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker process → SQLite `worker_owner` row | Process lifecycle state crosses into durable authority that blocks every replacement scheduler. |
| SIGTERM/SIGINT or scheduler result → lifecycle finalizer | A stop request must end scheduler authority before the durable lease is transferred. |
| stale owner → successor owner | Cleanup from an old process must never delete or overwrite a lease already acquired by a replacement. |
| cleanup collaborators → process-global ownership state | Browser/release exceptions must not leave globals claiming a worker is still active. |
