<interfaces>
Existing contracts to preserve:
- `runtime_state[key='worker_owner']` stores JSON durable authority; `WorkerLease` currently exposes worker ID and timestamps, while acquisition/renewal/release identify the owner only by worker ID.
- Scan rows use an opaque `lease_owner` token distinct from worker ID. `ScanLeaseHeartbeat` renews the row at no more than half its lease interval. Scan renewal/requeue/finish/fail require the matching live row token and deadline.
- Preview rows currently use worker ID as `lease_owner`; completion additionally rejects any newer revision. `finish_preview_in_transaction()` is called before title/thumbnail writes inside the app-owned transaction.
- `process_scan_requests(worker_id, ...)` and `process_preview_requests(worker_id)` are worker-injected compatibility processors. `WorkerServices.worker_id` is passed by `process_scans()` and `process_previews()`.
- Plan 01-19 keeps the durable lease until `scheduler.start()` returns/unwinds, makes signals request `shutdown(wait=False)`, and finalizes browser/lease/globals from the lifecycle thread.

Contracts introduced by this plan:
- Every acquisition creates a fresh opaque `WorkerLease.owner_token`; the token is stored in `runtime_state.worker_owner`, remains stable across renewal, and is rotated on every acquisition, including reuse of the same worker ID.
- Queue mutators receive worker ID and `worker_owner_token` separately from any queue-row token. A shared helper validates matching worker ID/token and `lease_until > now` using the caller's open write transaction before any queue mutation.
- Worker renew/release receive the exact acquisition token. Release remains allowed for the matching epoch during ordinary finalization even if its time lease elapsed, but can never remove a successor epoch.
- `WorkerServices` carries the acquisition token and one process-local admission/drain collaborator. That collaborator is only an in-process cancellation/join aid; SQLite remains authoritative.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker process → SQLite `runtime_state.worker_owner` | A process-presented ID/token crosses into the durable authority that elects one scheduler owner. |
| scheduler/app processor → scan and preview queue transactions | Row tokens, revisions, and worker epochs authorize durable shared-work mutations. |
| stale Worker A → successor Worker B | Expired authority and long row leases overlap across independent processes. |
| heartbeat executor → scheduler lifecycle thread | Lease loss must request shutdown without waiting on the executor that is currently running the heartbeat. |
| preview executor → Chromium cleanup | Browser use must finish before lifecycle cleanup closes the shared browser. |
