<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| retention clock/policy -> irreversible SQLite deletion | Injected UTC time and validated policy determine when historical evidence can be permanently removed. |
| durable retry state -> worker batch admission | Persisted state and due time decide whether a bucket may consume bounded write capacity. |
| source evidence -> aggregate savepoint | A retry may delete exact sources only after durable aggregate read-back succeeds. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-G05 | Tampering | hourly expiry | critical | mitigate | Bind a non-aligned cutoff and delete only rows whose stored bucket end is at or before it; regress both host and service tables. |
| T-02-G06 | Denial of Service | retry candidate selection | high | mitigate | Filter future/succeeded jobs before admission, use the due index/exact key, cap candidate materialization relative to policy, and retain deterministic global batch size. |
| T-02-G07 | Repudiation | retry attempt history | medium | mitigate | Preserve attempt/due/error state pre-due and increment exactly once only after an actual failed attempt. |
| T-02-G08 | Tampering | retry source deletion | critical | mitigate | Retain the existing savepoint rollback plus aggregate read-back, succeeded state, and exact-range delete ordering on every due retry. |
