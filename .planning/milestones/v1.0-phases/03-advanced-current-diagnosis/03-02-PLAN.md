<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| worker callback -> durable job health | Only the exact admitted worker epoch may publish outcome evidence; callbacks and exceptions are untrusted until authority is re-proven in the write transaction. |
| durable SQLite -> diagnosis projection | Stored metadata/runtime JSON/timestamps may be absent or malformed and must not create false health, SQL shape changes, or unbounded work. |
| diagnosis projection -> browser | Typed facts must remain distinct so the operator is not misled about availability, TLS, freshness, gaps, pending work, or cause. |

## STRIDE Threat Register (ASVS L1)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-06 | Tampering | background job outcome writers | high | mitigate | Begin an immediate transaction, assert exact `WorkerAuthority`, and mutate the outcome row in that same transaction; prove real worker takeover fencing. |
| T-03-07 | Spoofing | callback success/failure state | high | mitigate | Record success only after a non-false return, preserve success on later failure, record safe exception class, and test false/exception/LeaseLost paths. |
| T-03-08 | Elevation of Privilege | web diagnosis endpoint | high | mitigate | Keep job writers unreachable from Flask, expose GET only, reject selectors before SQLite, and source-test absence of worker operations. |
| T-03-09 | Denial of Service | service/pipeline snapshot queries | high | mitigate | Use one short transaction, fixed indexed queries, explicit caps/counts, active-service cutoff, no BLOBs/history scans, and query instrumentation in the API suite. |
| T-03-10 | Information Disclosure | job failure and effective settings | medium | mitigate | Persist/return bounded error class only, omit raw messages, worker epochs, paths, secrets, webhook URLs, and outbound allowlists. |
| T-03-11 | Spoofing | freshness/gap/TLS/availability projection | medium | mitigate | Preserve separate typed fields, derive freshness from evidence, and test simultaneous worker-fresh/stream-stale and TLS-unverified/service-online states. |
