<objective>
Make background-job health reported to the operator reflect what the job actually did -- for real, this time: an idle Pi's queue pollers stop being reported as permanently failed, a legitimately-running job stops being falsely flagged as stuck, a wedged startup job stops being permanently invisible, and a compound startup failure stops being silently downgraded to an unnamed warning.

Purpose: `03-VERIFICATION.md`'s round-4 report found the single ROADMAP truth this phase has failed for three consecutive rounds -- "Background-job health reported to the operator reflects what the job actually did" -- still false, in three independently reproduced ways. Two are new: 03-15's `job_outcome_unrecorded` promotion derives an expected *duration* from a poll *interval*, so it falsely fires on J6 (Chromium preview, 2s cadence) nine seconds into legitimate work and on J1 (heartbeat, 5s cadence) twenty-five seconds behind a maintenance lock `connect_db` itself allows thirty seconds for; and the same round's new `run_worker` catch site reads only the write error's class at a compound work-plus-write startup failure, so a genuine startup failure -- one this exact round added the field to carry -- reaches the operator as nothing. The third is not new: `dispatch_callback` has mapped a queue poller's normal-idle `False` return to a durable `failed` row since 03-02, missed by three prior verification rounds because every prior reproduction drove a synthetic callback rather than the real J5/J6 adapters this plan now drives directly.

Output: An idle Pi's Overview reads zero fabricated "Background job failed" cards; a legitimately-running job or a lock-waiting heartbeat is never promoted as stuck; a wedged startup job with no configured cadence is promoted exactly like any other overdue job; and a compound startup failure reaches the operator loudly instead of continuing on an unnamed warning.
</objective>
