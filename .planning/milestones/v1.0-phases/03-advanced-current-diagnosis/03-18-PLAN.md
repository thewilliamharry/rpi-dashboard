<objective>
Make the two queue pollers and the two discovery dispatchers return the verdict they already computed and durably recorded, instead of a constant that discards it -- closing the decisive half of `03-VERIFICATION.md` round 5's finding: "Background-job health reported to the operator reflects what the job actually did" is false in the fabricated-SUCCESS direction for J5, J6, J7 and J9, and no test in five rounds has driven the real production adapters against work that genuinely fails.

Purpose: Round 5 closed the fabricated-FAILURE direction completely (an idle Pi no longer reports two permanent failures). It left the mirror direction untouched: `worker_process_scan_requests` and `worker_process_preview_requests` each compute a real failure verdict, durably write it into `scan_requests` / `preview_requests`, and then `return True` unconditionally -- so `dispatch_callback`'s unchanged `if result is False:` mapping records the same dispatch as `succeeded`. `_run_scheduled_discovery` and `_run_startup_discovery` discard `run_discovery`'s own `'failed'` return entirely, falling off the end as `None` on both the skip path and the work path -- so `None` carries at least three meanings at the dispatch boundary, and the return-value vocabulary `03-17-SUMMARY.md` records as established ("None means no work was available") is not yet true of production for J7/J9. This is pre-existing (`82e3eaa`, 2026-08-06 for the pollers), not a round-5 regression, but round 4 set the precedent that provenance does not exempt a live untruth from this same failed truth.

Output: A queued scan or preview that genuinely fails is recorded as `failed` on its J5/J6 job-health row and surfaced as a `job_failed` operator exception, in the exact same dispatch that already writes the failure into the queue table. A scheduled or startup discovery that genuinely returns `'failed'` is recorded as `failed` on its J7/J9 job-health row; a genuine skip still records `succeeded`. This is proven by a regression that drives the real production adapters -- not a synthetic stand-in -- against work that genuinely fails, the exact test-scaffolding gap the verifier named as what let this defect through five rounds.
</objective>
