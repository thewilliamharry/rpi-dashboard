<objective>
Close the container time-zone gap the tracer's precondition names: install the IANA time-zone
database as a pinned Python dependency and plumb the operator's real zone name into the worker.

`python:3.12-slim-bookworm` ships no `/usr/share/zoneinfo` and `dashboard/Dockerfile` installs no
tzdata, so `ZoneInfo('Europe/London')` raises inside the built container even though it resolves
fine on a developer machine. Without this plan, every window in the phase silently evaluates against
UTC — a functional bug against D-02 that no unit test on a developer laptop can catch.

Purpose: make D-02's "the window lines up with the cron entry on the Pi" true in production, not
only in the test environment.

Ordering note (no circularity): plan 03.1-01 sits in Wave 1 and states a precondition that a named
IANA zone resolves. On a developer machine that precondition is satisfied by the host's own system
tzdata — verified: `ZoneInfo('America/New_York')` resolves today with no `tzdata` entry in
`dashboard/pyproject.toml`. This plan does not unblock 03.1-01; it closes the same gap for the built
container, which has no system tzdata to fall back on. The pin deliberately stays here rather than
moving into the tracer because installing it is gated behind Task 1's blocking package-legitimacy
checkpoint, which must not sit inside a Wave 1 tracer. On an executor with no system tzdata at all,
run this plan before 03.1-01.

Output: `tzdata` pinned in `dashboard/pyproject.toml` and `dashboard/uv.lock`, `TZ` plumbed through
`docker-compose.yml`, and a regression that fails if a named zone stops resolving.
</objective>
