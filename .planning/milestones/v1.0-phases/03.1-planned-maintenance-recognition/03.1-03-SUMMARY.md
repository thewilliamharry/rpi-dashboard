# Phase 03.1 Plan 03: Window CRUD Summary

**Maintenance windows are now created, edited, disabled, and removed entirely through the existing `PUT /api/service-meta/<port>` route -- server-side validation matches the UI-SPEC Copywriting Contract character for character, the window write shares the route's single commit with the metadata upsert, and migration 9 is proven additive and idempotent against every legacy database fixture the suite carries.**

## Performance

- **Duration:** ~45 min
- **Tasks:** 3
- **Files modified:** 7 (0 created)

## Accomplishments
- `dashboard/beacon/repositories.py`: `upsert_maintenance_windows(conn, *, port, windows, now)` -- replace-semantics write (delete-then-reinsert) on the caller's connection, opening no transaction of its own, matching `upsert_service_metadata`'s exact contract. Persists `weekdays` through `format_weekdays` so the stored text is exactly what `parse_weekdays` consumes on read.
- `dashboard/beacon/config.py`: two new `Settings` fields, `maintenance_default_grace_minutes` (default 15, `MAINTENANCE_DEFAULT_GRACE_MINUTES`) and `maintenance_windows_per_port_max` (default 50, `MAINTENANCE_WINDOWS_PER_PORT_MAX`), both through the existing `_positive_int` guarded-fallback helper.
- `dashboard/beacon/web.py`: `metadata_response` now decorates the repository row with a `windows` key -- a list of dicts (`id`, `start_minute`, `duration_minutes`, `weekdays` as sorted ISO integers, `grace_minutes`, `enabled` as a boolean), always present and empty rather than a missing key, on both the `GET` and `PUT` response.
- `dashboard/app.py`: `maintenance_windows` added to `allowed_fields`; `_validate_maintenance_windows` (module-level, identity-typed, runs before any connection opens) enforces every field bound with the exact Copywriting Contract error strings, index-prefixed 1-based; `upsert_maintenance_windows` is called inside the existing `with _db_lock:` block, after `upsert_service_metadata` and before the single `conn.commit()`, only when the field was present in the payload -- an omitted key leaves stored windows untouched, and the existing `sqlite3.Error` rollback path now covers both writes together.
- `tests/test_maintenance_windows.py`: `WindowPersistenceTests` (7), `SettingsBoundsTests` (2), `MetadataPayloadTests` (1), `WindowCrudApiTests` (8), `WindowValidationTests` (13), `WindowConcurrencyTests` (1), `ReadOnlyAdvancedTests` (1) -- 33 new tests, all passing.
- `tests/test_migrations.py`: `MigrationNineTests` (4 tests) -- migration 9 proven additive (table + four columns present via table-info pragma, never exception-catching), row-preserving, idempotent on re-application, and correctly registered `schema_changing=True`, run against every fixture in `FIXTURES` plus `operator/production.db`, `current-v4.db`, and `current-v6.db`.
