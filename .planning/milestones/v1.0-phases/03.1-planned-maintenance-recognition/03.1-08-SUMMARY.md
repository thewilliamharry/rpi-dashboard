# Phase 03.1 Plan 08: Suggestion Card (Operator Confirmation UI) Summary

**A dashed, colour-free suggestion card renders above the confirmed-window list only when the server returns an active suggestion, states the observed evidence in plain language, and offers exactly Confirm/Adjust -- both routing through the existing window-row builder to append an unsaved row, with no Dismiss control and no write until the operator clicks Save.**

## Accomplishments

- `dashboard/index.html`: populated the reserved `meta-suggestion` container (added hidden and empty by 03.1-05) with a `Suggested window` label reusing `.meta-label`, an evidence paragraph (`meta-suggestion-evidence`), and an actions row holding `Confirm` (`.meta-btn .meta-btn-primary`, `meta-suggestion-confirm`) and `Adjust` (`.meta-btn .meta-btn-ghost`, `meta-suggestion-adjust`) -- no third action, no dismiss control.
- `dashboard/style.css`: `.meta-suggestion` styled as dashed-`1px var(--border)`, `var(--muted)` text throughout, the modal's existing 12px form rhythm internally, plus a 4px `margin-bottom` that combines with the section's existing 12px flex gap to produce the UI-SPEC's 16px gap to the window list below; `.meta-suggestion-evidence` wraps at word boundaries (`overflow-wrap: anywhere`) and never truncates; both-theme coverage added to the existing `html.light` block; narrow-viewport rules stack the two actions vertically at 44px min-height, alongside the existing narrow-action rules. No new CSS custom property; neither `--accent2` nor `--accent3` appears anywhere in the suggestion rules.
- `dashboard/app.js`: `renderMaintenanceSuggestion(suggestion)` composes the Copywriting Contract's evidence sentence from the observed occurrence count, start/end clock times (via the existing `minutesToTimeValue` helper), and the weekday set (via a new `formatSuggestionWeekdays`, reusing the Monday-first `MAINTENANCE_WEEKDAYS` table), assigning it through `textContent`; it hides the card and clears `currentSuggestion` on absence. `loadMaintenanceWindowsForEditor` now also reads `meta.suggestion` from the same `GET /api/service-meta/<port>` payload as `windows` and calls `renderMaintenanceSuggestion` immediately after the window list renders -- a failed fetch leaves `suggestion` at its `null` default, so the card stays silently hidden with no error copy. `confirmMaintenanceSuggestion`/`adjustMaintenanceSuggestion` both call the existing `addMaintenanceWindowRow` with the suggested `start_minute`/`duration_minutes`/`weekdays`, the literal default grace (15), and `enabled: true`; Adjust additionally focuses the returned row's Start input. `openMetaEditor`/`closeMetaEditor` both reset `#meta-suggestion` to hidden and null `currentSuggestion`.
- `tests/test_ui_states.py`: `_service_meta` gained a `suggestion` keyword (defaulting to `None`); `_maintenance_route` gained `get_error` (simulates a failed `GET /api/service-meta/<port>`) and `put_calls` tracking (records every PUT's port and parsed body, letting tests assert "no write occurred" or inspect exactly what was saved). 10 new named Playwright tests cover: no-suggestion silence, failed-fetch silence, the rendered evidence sentence, exactly-two-actions, Confirm's unsaved append with zero network calls, Adjust's append-plus-focus, Save committing the suggested values verbatim, long-prose wrapping without truncation or horizontal overflow, colour-token exclusion in both themes, and non-appearance outside the modal.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `.meta-suggestion { display: flex }` overrode the `hidden` attribute, so the card stayed visibly rendered even with no suggestion**
- **Found during:** Task 3, writing `test_no_suggestion_renders_no_card_and_no_empty_state_message`
- **Issue:** `.meta-suggestion` (Task 1's own new rule) sets `display: flex` unconditionally, which wins the CSS cascade over the browser's built-in `[hidden] { display: none }` rule for elements with equal-or-lower specificity author rules. Setting `#meta-suggestion.hidden = true` therefore had no visible effect -- the card stayed rendered at `display: flex` with an empty evidence paragraph, directly contradicting this plan's own must-have truth ("absent when the server returns no suggestion -- an omission, not an empty-state message"). Verified independently with a Playwright probe against the live dev server (a `file://` load never applies the stylesheet and would have masked the bug).
- **Fix:** Added `.meta-suggestion[hidden] { display: none; }` immediately after the base rule, raising specificity so the `hidden` attribute reliably wins regardless of cascade-origin ordering.
- **Files modified:** `dashboard/style.css`
- **Verification:** The same Playwright probe now reports `display: none` with `hasAttribute('hidden') === true`; `test_no_suggestion_renders_no_card_and_no_empty_state_message` and `test_a_failed_metadata_fetch_renders_no_suggestion_and_no_error_copy` both pass.
- **Committed in:** `25b2aeb` (standalone fix commit, between Task 2 and Task 3)

**2. [Rule 1 - Bug] A pre-existing test's `.meta-btn` first-in-DOM-order selector broke once the suggestion card's own `.meta-btn` actions render earlier in the DOM**
- **Found during:** Task 3, running the plan's required regression command (`uv run --project dashboard python -m pytest -q`)
- **Issue:** `test_playwright_zero_one_many_states_in_dark_light_and_narrow_layout` (pre-existing, from an earlier phase) asserted `page.locator('.meta-btn').first.bounding_box()['height'] >= 44`. Before this plan, the first `.meta-btn` in DOM order was `#meta-window-add` (always visible). This plan's Task 1 markup places `#meta-suggestion-confirm`/`#meta-suggestion-adjust` (both `.meta-btn`) earlier in the DOM, inside the `meta-suggestion` container -- and that container is hidden by default when a service (as in this test's fixture) carries no `suggestion` field. Playwright's `bounding_box()` returns `None` for a hidden element, causing a `TypeError` on subscript.
- **Fix:** Changed the assertion's target from `.meta-btn` first-in-DOM-order to the always-visible `#meta-cancel`, preserving the original assertion's intent (a `.meta-btn` meets the 44px narrow-viewport touch target) without depending on DOM order.
- **Files modified:** `tests/test_ui_states.py`
- **Verification:** `test_playwright_zero_one_many_states_in_dark_light_and_narrow_layout` passes; full suite green.
- **Committed in:** `0e73ca9` (Task 3 commit)
