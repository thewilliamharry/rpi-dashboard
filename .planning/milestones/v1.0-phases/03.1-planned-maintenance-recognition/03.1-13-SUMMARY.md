# Phase 03.1 Plan 13: Web Connection Lease Release Summary

**Every connection dashboard/app.py opens now flows through `with _db_lock, database_access(DB_PATH) as conn:`, releasing its shared maintenance lease on every exit path -- closing G-03.1-2's third defect, the web-process lease leak that starved the worker's exclusive migration lock -- pinned by an end-to-end regression and an AST structural gate.**

## Performance

- **Duration:** ~40 min
- **Tasks:** 2
- **Files modified:** 3 (`dashboard/app.py`, `tests/test_api_and_auth.py`, `tests/test_module_boundaries.py`)

## Accomplishments

- All 24 `with _db_lock:` / `conn = get_db()` sites in `dashboard/app.py` merged into a single `with _db_lock, database_access(DB_PATH) as conn:` statement; every `conn.close()` inside those blocks (including six across the service-metadata PUT route's early-return branches) removed, since the context manager now owns the close on every exit path.
- Three finally-suite exceptions treated individually per their shape: `_mutation_write_transaction` and the preview-publish block (each had an `except` clause alongside `finally`) had only the `finally:` clause removed; the telemetry-history block (a bare `try`/`finally` with no handler) had the whole scaffold removed and its body folded one level into the merged `with`.
- `init_db`'s compatibility repair converted from `get_db()` + `try`/`finally` to `with database_access(DB_PATH) as conn:` -- syntactically distinct from the telemetry-history case because `init_db`'s `conn = get_db()` was never nested an extra level under `with _db_lock:`, so no body line moves here (documented as a key-decision above).
- `_set_runtime_state`/`_get_runtime_state` split into private row-level helpers (`_write_runtime_state_row`, `_read_runtime_state_row`) plus ownership branching: a caller-supplied connection is used directly (never closed or committed by the helper); a self-opened connection is scoped to a `with database_access(DB_PATH) as conn:` block that ends at exactly the point the old code called `.close()` -- in `_get_runtime_state`'s case, before the JSON decode, empty-row check, and fallback, none of which now run while the lease is held.
- `_worker_write_transaction` (the authority-path connection, opened via `connect_db` directly and already owning its close in its own `finally` suite) deliberately left untouched, as the plan required.
- `get_db()` kept defined and importable, with a one-line docstring noting it is now a test-owned seam; twelve test modules call it directly.
- Two new regressions in `tests/test_api_and_auth.py` prove the release end-to-end: one reproduces the Pi's schema-version-8 state (dropping `maintenance_windows` and the three migration-9 `events` columns) and asserts, for both `/api/services` and `/api/events`, a loud 500, every spied connection's lease released, and the migrator's own `exclusive_database_maintenance` acquirable at a zero timeout; the second proves the same three assertions after an unrelated repository call is patched to raise, showing the invariant belongs to the exit path rather than to one missing table.
- A new AST structural gate in `tests/test_module_boundaries.py` walks `dashboard/app.py` and forbids any assignment bound to a call to the `get_db` seam, without flagging `_worker_write_transaction`'s deliberate `connect_db` binding on the authority path.
