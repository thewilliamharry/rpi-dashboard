<objective>
`detect_suggestion` clusters observations by raw minute-of-day distance,
`abs(o['start_minute'] - anchor['start_minute'])`, with no wraparound
(`dashboard/beacon/maintenance.py:255-260`). Minute-of-day is a position on a dial that closes at
1440, and this arithmetic treats it as a number line.

The gap is narrower than 03.1-REVIEW.md implied, and the plan states the narrowing rather than
inheriting the wider claim: a FIXED-time nightly restart at 23:55 clusters perfectly well today —
every observation's `start_minute` is 1435, so the raw distance is zero and only the recovery crosses
midnight. What fails is a restart whose START time itself jitters across midnight. Measured against
the shipped tolerances (start 900s, duration 600s): starts of 23:55 / 00:00 / 00:05 / 23:58 give
minute-of-day values `[1435, 0, 5, 1438]` whose maximum raw pairwise distance is 1438 minutes against
a 15-minute tolerance, and `detect_suggestion` returns `None`. The identical ±5-minute jitter around
04:00 gives `[235, 240, 245, 238]`, a maximum distance of 10 minutes, and returns a suggestion. Same
pattern, same jitter, different hour, opposite answer. That is MNT-02 failing for the single most
common real-world case it exists to serve — the nightly cron restart.

**The second half is the one that matters more, and it is why this plan does not stop at the
distance.** Fixing only the comparison makes the cluster form and then hands its start minute to a
naive `median`. A naive median of `[1435, 0, 5, 1438]` is roughly 720 — midday. The operator would be
offered a lunchtime maintenance window for a midnight restart, presented with the same plain-language
evidence sentence and the same confidence as a correct one. That is strictly worse than today's
silence. The distance and the median must close the dial together or not at all.

**And a third consequence, recorded rather than left silent.** `suggestion_overlaps_enabled_window`
compares the same clock positions with the same raw distance and carries the same defect. Today it is
unreachable, because a midnight-straddling suggestion cannot be produced. This plan makes one
producible, which makes that path reachable for the first time — verified: a suggestion at minute
1439 against an enabled window at minute 0 returns `False` today, so the operator would be asked to
confirm a window they already own, which is exactly what RESEARCH Q3's withholding rule exists to
prevent. Leaving it for a later round would be this phase's established failure mode: fix the
instance you enumerated, ship a gate that recognises only the shape you just fixed.

Purpose: make MNT-02 work at every hour of the day, including the hour operators actually schedule
restarts in, without trading a missing answer for a wrong one.

Output: a closed dial in the two places minute-of-day is compared, a cluster median computed on that
same dial, and regressions that were each observed red against the code they replace.
</objective>

<decision_coverage_note>
This plan restores **D-12** ("recomputed against the service's recent outage evidence rather than
frozen at first detection ... a proposal matching what the service has actually been doing lately")
for patterns that straddle midnight, which today produce no proposal at all, and preserves **D-11**
(the suggestion surfaces only inside the editor, inactive until confirmed) and **D-02**'s wall-clock
literal rule, which is what makes minute-of-day the right unit to compare in the first place. It is
the detection-side mirror of **D-03**'s observation that "a start time plus a duration crosses
midnight naturally, so no separate midnight rule is needed" — true of coverage, and provably not true
of detection. D-01 and D-04 through D-10 are cited only as non-regression obligations in
`must_haves.truths`.
</decision_coverage_note>
