## Explicit assumptions recorded by this plan

- **A-08 — the availability/status column is deliberately not changed.** `serviceAvailability`
  renders `● maintenance` / `● unknown` / `● offline` / `● online` in the Services table's *status*
  column, pinned by four existing assertions (`tests/test_advanced_ui.py:1879,1903,1923,1949`).
  That column answers "is it up", the freshness column answers "how current is the evidence", and
  Beacon's standing convention is that distinct facts stay distinct. This plan changes only the
  freshness vocabulary. A future phase that wants one shared glyph vocabulary across both columns
  must say so and re-pin those four assertions.
- **A-09 — `fresh` gets a presentation too.** The UI-SPEC's Six States table names only the six
  requirement states, but `fresh` shares the freshness column with three of them. Leaving it as a
  raw lowercase literal beside three capitalised, glyphed siblings would be an inconsistency the
  spec did not intend, so `fresh` is presented as `● Fresh` with `--green` (the Color contract's
  existing "Fresh / online" row). The bullet glyph is unchanged from today.
- **A-10 — filter option labels change, filter values do not.** The Freshness filter's `aging`
  option is relabelled `Degraded`; its `value="aging"` and the sort ordering array keep the
  server's wire literals, so a rename on either side stays a server-side rename.
- **A-11 — `freshnessWord` becomes the single lowercase form.** The active-exception copy already
  interpolates `freshnessWord(state)` into sentences. It is extended to return `degraded` for
  `aging` so exception copy and badge copy cannot drift apart; it stays lowercase because it
  appears mid-sentence.
- **A-34 — light-mode `--green` fails AA for `.freshness-fresh`, and the fix is deferred to a
  human.** `.freshness-fresh` resolves `var(--green)`. Light-mode `--green` is `#16a34a`
  (`style.css:36`) and scores **3.30:1** against the light body surface `#ffffff` — 3.08:1 against
  `--bg3` `#f7f7f7` — under the 4.5:1 AA minimum this plan's Task 1 states for these badges. Task 3
  therefore asserts contrast for `.freshness-stale`, `.freshness-unknown` and `.freshness-degraded`
  only, and **deliberately exempts** `.freshness-fresh`. Exempted rather than fixed because `--green`
  is an app-wide token whose consumers sit outside this plan's scope — `.svc-online`
  (`style.css:498`) renders it as 10px text, `.evt-up .evt-title` (`style.css:1128`) as body text,
  and `.scan-pip.ready` (`style.css:153`), `.us.up` (`style.css:565`) and `.hist-band-online`
  (`advanced.css:213`) as fills — so darkening it is a whole-light-theme token decision, not a
  targeted edit. **Awaiting a human decision**; recorded as tracked debt in `05-DEBT.md` so a later
  verifier reads the exemption rather than re-deriving it. Numbered A-34 because it was added in a
  later planning revision: reusing 05-02's A-08–A-11 block would have shifted every downstream
  assumption ID in the phase.
