## Explicit assumptions recorded by this plan

- **A-18 — the uptime strip gets an accessible name, not a tab stop.** `05-PATTERNS.md` calls the
  strip's title-only hint a confirmed partial gap; `05-UI-SPEC.md` calls it compliant. This plan
  adopts the superset that satisfies both readings at no visual cost: each segment gains the image
  role and an `aria-label` equal to the string its `title` already carries. It does **not** gain
  `tabindex` — a seven-day strip on every service card would insert dozens of tab stops into the
  main dashboard's primary flow for an element that carries no action, and the coverage strip
  (which the UI-SPEC does require to be focusable) is the surface where per-segment keyboard
  inspection genuinely belongs. This resolves `05-CONTEXT.md` Open Question 1.
- **A-19 — `05-RESEARCH.md` assumption A4 is resolved as the UI-SPEC proposes, and pinned.**
  Focusable **and actionable** uses the button role; focusable and **disclosure-only** uses the
  image role. `renderServiceStateBand`'s segment and `renderPointTargets`' hit-circle are correct
  as they stand and are not changed. A test pins the convention across every focusable element in
  the history section, so a sixth focusable element cannot be added without a decision.
- **A-20 — the keyboard range gesture reports the same origin as the mouse drag.** The applied
  range carries `origin: 'drag'`, so the range stack, the range label and every downstream
  behaviour are identical whichever gesture produced it. Introducing a distinct origin would fork
  a contract Phase 4 verified.
- **A-21 — the pending anchor reuses the drag overlay element, collapsed to zero width.** The
  existing overlay already draws a one-pixel accent border on each side, so a zero-width overlay
  renders as a two-pixel accent edge with no new CSS and no second visual language.
- **A-22 — `Escape` cancels the pending anchor through the existing window-level listener.** The
  time-cursor binding already registers a window `keydown` Escape handler; extending it is one
  listener, not a second global key handler.
- **A-23 — point targets keep the image role even though they now respond to keys.** The keys they
  respond to select a range on the *chart*, not on the point; the point itself still activates
  nothing and discloses only. Recorded so a later reader does not read this as a violation of A-19.
