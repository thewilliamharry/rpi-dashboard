it honest.

`05-CONTEXT.md` D-02 forbids a second mechanism. The existing `density-comfortable` /
`density-compact` body classes — today three padding rules — become the input to the default

workspace is proven identical in both themes, and every container that starts closed is proven to
open with one activation onto identical content.

evocative enough to justify redesigning the workspace. The scope here is the UI-SPEC's short named

## Explicit assumptions recorded by this plan

- **A-24 — a re-render never resets a disclosure; an explicit density change does.** The UI-SPEC
  requires that density set the initial state only and never force a container back on every
  re-render. This plan implements that literally for re-renders (refresh polls, range changes,
  service changes). It additionally decides that changing the density preference from the Settings
  select **does** re-apply the defaults and clear the per-instance overrides, because choosing a
  density is itself an explicit request for that density's presentation. Recorded because the
  UI-SPEC is silent on this case.
- **A-25 — per-instance overrides are pruned to what is on screen.** The incident-row override
  record is a map keyed by episode identity. After each incidents render it is pruned to the keys
  just rendered, so it stays bounded without any bounds-or-filters comparison. Consequence,
  recorded honestly: returning to a previously-viewed range does not restore that range's
  overrides. This is the cheapest bounded rule that satisfies "a re-render never clobbers".
- **A-26 — episode identity is port plus down timestamp.** No episode identifier exists in the
  payload; the port and the down timestamp together are the stable pair every episode carries and
  the pair the existing incident rendering already keys its display on.
- **A-27 — the stale incident count is pulled into this phase deliberately.** `05-CONTEXT.md`
  lists it as tracked debt outside Phase 5's scope "unless the planner argues otherwise". It is
  pulled in: a previous render's populated count standing beside an error banner blurs the
  populated state and the error state, which is exactly what criterion 4 forbids. It is a
  contained change on one early-return path in the same file this plan already edits.
- **A-28 — one new copy string, decided here.** The unavailable-count reading is
  `Incident count unavailable`, matching the existing element's own `(total unavailable)` idiom.
  `05-UI-SPEC.md`'s Copywriting Contract does not cover this element, so this string is a
  planner decision recorded in this plan's Copywriting Contract table.
- **A-29 — no other surface gains a density-driven disclosure default.** The UI-SPEC's two-surface
  list is treated as the complete scope, not a starting point. A third surface requires its own
  decision.

descriptor; do not assert `sum(counter.values())` instead, because a `Counter` makes that sum equal
the element count for every possible input and so proves nothing. This descriptor is the backbone of

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → advanced.js | The persisted density preference selects the default disclosure state of two containers |
| Flask → browser DOM | Episode identity fields compose the in-memory override keys |
| in-memory override records → every subsequent render | Unbounded growth of a per-instance record would be a slow resource leak in a long-lived dashboard tab |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-18 | Tampering | the stored density preference | low | mitigate | Unchanged existing strict allowlist in `loadPreferences`: only the two recognised values are accepted and anything else resolves to the theme default; no new persisted key is introduced, asserted by a plan gate on the saved key set |
| T-05-19 | Denial of service (memory) | the incident override map | low | mitigate | Pruned after every incidents render to only the keys just rendered, so the record is bounded by one range's episode count regardless of how long the tab stays open |
