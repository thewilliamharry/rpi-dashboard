<objective>
The rest of the surface, and the front page that has to survive it.

`07-01` proved the toggle end to end on `/api/advanced/current`. This plan expands the same shape
horizontally to the three remaining routes, and then does the one genuinely delicate thing in this
phase: it takes the entry point out of the front page's served bytes without breaking the front page.

**The front page's script is not as decoupled as it looks.** `dashboard/app.js:772` runs
`$('advanced-diagnosis-link').addEventListener('click', captureDashboardScroll)` inside the
`DOMContentLoaded` handler with no guard. Remove the anchor and that expression raises a
`TypeError`, the handler dies at line 772, and **every statement after it never runs** — the meta
form, the modal, the maintenance-suggestion buttons, the initial `Promise.allSettled` fetch of stats,
history, scan, services and events, and all four polling intervals. The services front page the
operator explicitly said they like would be a static shell. This is the single highest-risk change in
the phase and the reason its proof is a real browser rather than a source assertion.

**How the front page learns the toggle: the server decides, before the bytes leave.** The open
question `07-CONTEXT` posed is settled here. `/` serves `dashboard/index.html` through `send_file`
today, and criterion 2 requires the entry point be absent rather than styled away, so the choice is
where the removal happens.

- *Rejected — client-side removal after a configuration fetch.* `dashboard/app.js` does not fetch
  `/api/config` today (only `dashboard/advanced.js` does, at its line 468), so this adds a boot
  round-trip to the page whose responsiveness is the product's core value; the link still ships in
  the document and is only taken out afterwards; and a client with scripting disabled keeps it.
- *Rejected — a wrapper element around the anchor in `index.html`, toggled server-side.* Editing
  `index.html` moves the enabled bytes, which is precisely what criterion 4 and `07-01`'s captured
  digests forbid.
- *Rejected — a second front-page file for the disabled mode.* Two documents to keep in step, and
  every future front-page change silently becomes two changes.
- **Chosen (D-07-05):** `/` keeps its current `send_file` statement verbatim on the enabled path, and
  on the disabled path serves a once-computed transform of the same file with the anchor and its
  trailing separator removed. The enabled path is byte-identical by construction rather than by
  test — the test exists to catch a future edit that breaks the construction.

**Purpose:** complete criterion 2, without costing criterion 3 or breaking the page criterion 1
protects.
**Output:** three more gated routes; `dashboard/beacon/frontpage.py`; a front page that boots with or
without its advanced link; and browser-level proof of both.
</objective>

<plan_review>
**The one place a source assertion appears, and why it is not the evidence.** Task 2's markup
invariant reads `dashboard/index.html` and counts pattern matches. That is inspection, and it is
knowingly so: it is not evidence that the feature works, it is a tripwire that converts a future edit
to line 24 from a production failure into a test failure. The evidence that the feature works is the
served body in Task 2 and the rendered page in Task 3. The invariant's message must say which of the
two it is, so a later reader cannot mistake it for a behavioural guard.

**Task 3 covers two sites, and one of them is invisible by default.** `dashboard/app.js` reaches the
anchor twice, and only the `DOMContentLoaded` registration is exercised by loading the page.
`restoreDashboardScroll`'s focus call is behind an early return that a freshly navigated browser
never passes, so the obvious version of this test would guard one site, pass, and leave the other
free to throw — a test blind to half the surface `D-07-06` and `T-07-07` claim. The seeded
`DASHBOARD_SCROLL_KEY` subtest exists solely to reach it, and the acceptance criteria split the
mutation per site so neither guard can be removed without a named subtest going red.

**Task 3's assertion hierarchy is stated rather than blurred.** Three things are checked after the
front page loads with the link gone. Only one of them can actually fail if the defect is present.
The theme toggle is registered *above* the breaking line, so it would keep working with the boot
broken — it is a control that proves the page is alive at all, not that the boot completed. The empty
`pageerror` list is genuine but indirect: a swallowed error would not appear. The populated services
grid is the real evidence, because populating it requires execution to have reached the
`Promise.allSettled` call fifteen statements below the break. The plan says which is which because a
test that presents three assertions as three proofs, when two of them cannot fail, is exactly the
"looks stronger than it is" pattern Phase 6 found six times.

**Outcome over mechanism, and where the exception is.** Criterion 2's outcome is "the entry point is
absent". This plan fixes a mechanism — server-side excision of a specific markup span — because the
three alternatives each fail a different criterion, and the objective records which. The mechanism
can be wrong in exactly one way: `without_advanced_entry_point`'s pattern is coupled to markup it
does not own. The consequences of that coupling breaking are bounded deliberately — the transform
raises rather than returning a document that still carries the link, and the markup invariant fires
first, in the test suite, before any deployment sees it.

**No absolute thresholds.** The only literals compared against are counts of one and zero, and the
identity of two byte strings. Nothing is tied to a machine, a duration or a dataset size.

**Every new guard is mutation-verified with recorded observed values**, and each acceptance criterion
names the specific mutation and the specific values to record. Task 3's mutation is the important
one: reverting only the JavaScript guard, leaving the server change in place, is precisely the
half-shipped state that would otherwise reach the operator.

**Reversibility.** Nothing here is one-way. A new pure module, one branch, a process-local cache, and
two guarded lookups in a script. No migration, no schema change, no write. The advanced asset files
stay in the production image specifically so that turning the toggle back on and restarting restores
the workspace with nothing else to do, which is criterion 5's requirement and is asserted by keeping
`test_production_image_manifest_includes_the_advanced_document_bundle` green.
