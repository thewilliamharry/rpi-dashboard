## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → mutation/queue API → SQLite | User actions during worker loss must persist exactly once and remain bounded. |
| worker heartbeat/events → browser state | Asynchronous health data controls prominent stale/recovery messaging. |
| service metadata → rendered DOM | Long or adversarial-looking text must remain text, bounded, and non-executable. |

## STRIDE Threat Register — OWASP ASVS L1

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-61 | Spoofing | Stale/fresh monitoring state | medium | mitigate | Derive state from production heartbeat data and prove same-document recovery plus gap event with a real browser. |
| T-01-62 | Tampering | Durable requests while worker is unavailable | high | mitigate | Assert real queue rows, no premature claim, bounded expiry, and fenced recovery processing in SQLite-backed integration tests. |
| T-01-63 | Information Disclosure | Service metadata rendering | medium | mitigate | Render through existing text-only paths and assert long content remains bounded without HTML interpretation. |
| T-01-64 | Denial of Service | Long/narrow UI content | low | mitigate | Rendered bounding-box and overflow assertions cover two themes and viewport extremes. |
| T-01-65 | Repudiation | Monitoring outage recovery | medium | mitigate | Persist the outage interval as a monitoring-gap event and announce one recovery transition. |
</threat_model>
