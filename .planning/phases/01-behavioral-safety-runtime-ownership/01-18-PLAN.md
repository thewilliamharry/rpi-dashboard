<interfaces>
Existing contracts to preserve:
- `outbound.RETRIEVAL_METHODS` is exactly `GET` and `HEAD`; `route_browser_request(policy, route) -> bool` rejects every other HTTP method before policy planning or continuation.
- `PolicyProxy` remains loopback-only, validates every plain request/CONNECT authority, opens only `RequestPlan.selected_address`, preserves original Host/TLS SNI, and bounds relay capacity. CONNECT must remain available for ordinary HTTPS HTTP retrieval.
- `_legacy_screenshot_service()` creates a context through `browser_proxy_context(...)`, registers the HTTP route today, and calls `context.new_page()` before navigating and capturing.
- The installed Playwright 1.61 `BrowserContext.route_web_socket(url, handler)` applies to sockets created after registration. A routed `WebSocketRoute` does not connect to the server unless `connect_to_server()` is called, and `close(code=..., reason=...)` closes the browser side.

Transport contract introduced by this plan:
- `browser_proxy_context()` installs both the existing HTTP route gate and a catch-all WebSocket gate before yielding the context; callers cannot create a page before either gate exists.
- `block_browser_web_socket(web_socket_route)` immediately closes the routed socket with a stable destination-free policy close and never calls `connect_to_server()`.
- HTTPS main-frame and subresource GET/HEAD requests continue through `PolicyProxy` unchanged; WSS and other Playwright WebSocket attempts receive no origin connection or duplex relay.

| Boundary | Description |
|----------|-------------|
| hostile HTTPS preview document → Chromium context | Untrusted page JavaScript can create WebSockets immediately and attempt duplex mutation against any otherwise approved service target. |
