<objective>
Close all three remaining BLOCKER gaps in `03-VERIFICATION.md`, every one of them inside `compose_pipeline_diagnosis` / `compose_active_exceptions`: derive `open` per coverage row instead of from the stream, map the durable `reason` discriminator to its own exception kind instead of hard-coding `collection_gap`, and make `gaps.count` and `gaps.truncated` describe the same bounded population.

Purpose: The Active Exceptions list is the single operator-facing safety surface of this phase. Today one real open gap inflates it with month-old resolved intervals and retention-deleted history, a host with no thermal sensor is reported as a permanent collection failure, and 65 open gaps can hide behind `truncated: false`. Evidence that cries wolf on resolved history fails TEL-06's contract outright.
Output: A gap projection in which every `open`, `actionable`, and `kind` label is derivable from the durable row it describes, bounded so its completeness claim is true, with the CR-01-asserting test corrected rather than preserved.

This is the lead plan of the phase's gap-closure round and carries its tracer: Task 1 proves the corrected labelling end to end (SQLite row -> repository read -> composer -> JSON -> browser DOM) before Tasks 2 and 3 expand out from it. Plans 03-09 and 03-10 build on this plan's payload.
</objective>

<interfaces>
- `telemetry_coverage` (`migrations.py:254-263`) constrains `reason` to exactly four values -- `collection_gap`, `unknown`, `expired`, `not_yet_monitored` -- and constrains `end_ts > start_ts`. A persisted row is therefore a **closed interval by construction**: it is written only when an interval is already bounded. It can never itself represent a currently open gap.
- `telemetry_streams.open_gap_start_ts` is the ONLY durable representation of a currently open gap. It is a **stream-level** fact. The 03-07 synthesis pass (`diagnosis.py:218-233`) is the only legitimate producer of `open: true` items.
- `read_pipeline_evidence(conn, *, now, gap_limit=48, stream_limit=64, pending_limit=32)` already normalizes each limit into a local and already returns `gaps_truncated`, `streams_truncated`, and `pending_truncated` as sentinel-measured booleans. It does NOT currently return the applied gap limit, so the composer has no bound to slice the combined list against; this plan adds that one key.
- `compose_pipeline_diagnosis(evidence, settings, *, now)` builds `gaps` in two passes (coverage rows, then stream synthesis) and returns `{'items', 'count', 'truncated'}`. `count` is `len(gaps)` over BOTH passes while `truncated` reads only `evidence['gaps_truncated']` -- the two describe different populations, which is blocker 3.
- `compose_active_exceptions(host, services, pipeline, *, recovery_required)` promotes `pipeline['gaps']['items']` at `priority: 5` with a hard-coded `kind: 'collection_gap'`, spreading `**gap` (which carries `reason`) into the exception while ignoring it -- blocker 2. Its final `sorted(...)` key is `(priority, kind, port, job_id)` and Python's sort is stable.
- `get_current_diagnosis` is the sole caller of both composers; `dashboard/advanced.js::renderPipeline` and `::renderOverview` are the sole consumers of the resulting payload. `advanced.js` does not read `schema_version`.
- Each gap item dict is referenced from BOTH the flat `gaps` list and its stream's `stream['gaps']` list; they are the same objects, so a field written once is visible in both places.
</interfaces>

<assumption_delta_decision>
Noun: `pipeline.gaps` completeness contract (`count` / `truncated`).
Decision: promote -- bound the combined coverage+synthesized list to the durable read's own gap limit after a stability-preserving open-first/actionable-first sort, and OR `streams_truncated` into the disclosure. Rejected alternative: returning synthesized items as a separately typed `open_gaps` field with its own count/truncated pair. Rationale: the separately typed option is closer to the phase's "separately typed evidence" convention, but it splits one operator-facing region into two, forces a second browser contract change in the same round, and leaves the operator to mentally re-join two lists to answer "are there gaps?". Bounding one population against one limit is the smaller truthful change and matches the 03-07 precedent that a cap must never hide actionable evidence.
</assumption_delta_decision>
