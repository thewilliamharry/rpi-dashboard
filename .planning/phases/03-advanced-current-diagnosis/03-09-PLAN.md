<objective>
Make the Overview exception list -- the single operator-facing safety surface of this phase -- actually readable, and stop the workspace from discarding the operator's own choices underneath them: give every exception kind real operator copy, keep the chosen service sort across refreshes, and stop an unknown section value from blanking the page.

Purpose: Plan 03-08 makes the server's exception evidence true; this plan makes it legible. Today every card falls through two dead fields to a raw kind such as `host_freshness` above the words "Unknown evidence", the operator's sort reverts within 5-15 seconds of choosing it, and an unrecognised section id hides every section and then raises on a null dereference. Plan 03-08 adds a further kind (`coverage_unknown`), which makes raw-identifier rendering worse rather than better.
Output: A kind-to-copy projection covering every emitted kind plus an explicit unrecognised-kind branch, a service sort that survives polling, a guarded section selector, and a refresh error region that can name a server-supplied cause.

Expansion plan: the phase tracer is plan 03-08 Task 1. This plan expands outward from that proven slice into the browser layer.
</objective>

<ui_spec_reconciliation>
`03-UI-SPEC.md` "Service diagnosis" currently states that a user sort supersedes default operational ordering "until filters are cleared, **the table is refreshed**, or the user chooses `Reset operational order`". Taken literally with a 5-15 second poll, that clause makes a user sort unusable, and both `03-VERIFICATION.md` (DIA-08 BLOCKED, "the auto-refresh sort reset also defeats a supported presentation preference") and `03-REVIEW.md` WR-03 rule the shipped behaviour a defect. The reconciliation adopted here is that "refreshed" was written to mean an operator-initiated re-fetch, and that the contract already provides an explicit control -- `Reset operational order` -- for exactly the intent that clause was reaching for. Task 2 therefore preserves the sort across every refresh and amends the one UI-SPEC sentence so the contract and the shipped behaviour agree rather than leaving a documented contradiction. Flagged as a planner interpretation, not a locked decision: no `D-NN` in `03-CONTEXT.md` speaks to sort persistence across refresh (D-14 lists theme, refresh interval, density, range and filters as the persisted preferences and does not mention sort), so the sort remains session-local memory state and is deliberately NOT added to `beacon-advanced-preferences-v1`.
</ui_spec_reconciliation>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server JSON -> browser DOM | Exception `kind`, `section`, `name`, `detail` and stream keys all originate outside the rendering code and reach the DOM and the section selector. |
| operator input -> shared browser state | Sort, filters and expansion are operator intent held in memory alongside server-driven state; a render pass must not silently overwrite intent. |
| refresh error path -> operator interpretation | The error region is what the operator reads to decide whether to retry, wait, or investigate; a wrong cause sends them the wrong way. |
