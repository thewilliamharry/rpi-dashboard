<objective>
Make the per-service collection-gap evidence real, and make it read like something a person wrote. Join each service to the gap items already composed for its own stream, disclose how complete that evidence is, and replace the serialized container in the expanded detail row with operator copy.

Purpose: `compose_service_diagnosis` sets `collection_gaps` to a hardcoded empty list that nothing in the module ever populates, while the composer does attach per-stream gaps and never per-service ones. The renderer then serializes that container straight into the detail row, so every expanded service row currently reads as an empty bracket pair -- and because an empty container is truthy, the no-evidence fallback beside it is unreachable. That is a hollow property presented to the operator as evidence, on the surface the phase goal names by its own words.
Output: A service detail row whose gap evidence is joined from durable composition, states its own completeness, and reads as English.

Tracer note: gap closure against a wired system, so tracer-first is honoured in shape. Task 1 is the vertical slice -- durable stream gaps, through the join, through the endpoint, asserted on the composed payload. Task 2 expands that proven slice to the operator's eyes in a real browser.
</objective>

## Populate versus drop `collection_gaps`

The verifier offered two closures and asked for one to be chosen, justified, and rated. **This plan populates the field.**

Why populate rather than drop: dropping it and rendering a fixed no-evidence string would replace a hollow property with a *false* one. The code would assert that a service has no gap evidence without ever having looked, which is the same prohibition class the phase already failed for -- an operator-facing claim not derivable from any durable row. The evidence is already computed one function away: `compose_pipeline_diagnosis` builds `stream['gaps']` for every stream, including service streams keyed by port. Joining it is a lookup, not new machinery.

Why the join carries a completeness state: the phase's hard-won lesson from prior Gap 3 is that a count and a truncation flag must describe the same population. A second, per-service view of gap evidence would reintroduce exactly that hazard if it silently inherited the bounds of a different read. So the per-service block carries its own four-state disclosure, each state derived from a durable read fact -- never a default, never an inference.

Rated `costly`, not `one-way`: this changes the shape of a read-model field and bumps the read model's version. It has exactly one consumer, the project's own browser bundle, plus its test fixtures. There is no migration, no persisted data, no external contract, and no third party to coordinate with. It is rated costly rather than reversible because it introduces an operator-facing evidence surface which, once trusted on hardware, is awkward to withdraw. No `checkpoint:decision` is inserted, because the decision is reversible in one revert.
</decision_record>

| durable stream gap rows -> per-service claim | A stream-level fact must not become a per-service assertion without an explicit, derived completeness state. |

| read-model shape -> stale consumer | A field whose shape changes without a version change can be silently misread. |
