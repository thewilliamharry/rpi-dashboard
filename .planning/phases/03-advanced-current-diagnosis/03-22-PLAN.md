The distinction must be made where the classes are still distinguishable." This plan's Task 1 makes the distinction at `_get_browser()` -- the one call inside `_legacy_screenshot_service` that is unambiguously the shared browser machinery and not yet any fact about the previewed service -- and carries it to `worker_process_preview_requests` through the existing `thumb_error` return slot, which already survives both blanket handlers unmodified. Neither blanket handler is narrowed; narrowing app.py:982 alone was proven this round NOT to close the gap, because app.py:930 keeps it fully live.

This round closes the polarity the round-7 verifier reproduced twice on a real SQLite database through the real production adapters, plus the two lower-severity residuals it folded into the same two gaps.
