restart covered by a real maintenance window is recorded truthfully and silently.

This is the architecturally risky spine of the whole phase — DST-correct local wall-clock window
matching (D-02), freeze-at-write suppression boundaries (D-08 / RESEARCH A4), and a coverage read
that shares exactly one write transaction with the tagged event insert (Pitfall 6). Every later
plan in this phase expands horizontally out from this proven slice; none of them re-open it.

Purpose: prove end-to-end, on one path, that suppression is a tag on a retained row and never a
withheld row — before any editor markup, suggestion detector, overrun evaluator, or presentation
work is built on top of it.

reads, `Settings.timezone`, the suppression tagging seam inside both transition funnels, and a new
pytest module that drives a real down-then-recover restart through the worker functions.

Six files are touched because the tracer is a single vertical path and splitting it would destroy
the end-to-end verification that is the entire point of a tracer. Each individual edit is small and
has an exact analog named in `03.1-PATTERNS.md`.

  <decision>The exact stored schema for maintenance windows and suppression bookkeeping, which becomes migration 9 and cannot be narrowed later without a data migration.</decision>
  <context>
Three locked decisions become durable schema here and each is rated one-way in 03.1-CONTEXT.md:

  - D-03: a window is a start time + a duration + a weekday set (no cron expression field). Widening
    the shape later needs a migration.
  - D-05: several windows per service, stored as a list keyed by port. A list-per-service table
    cannot later be reduced to one row per port without discarding operator data.
  - D-10: the suppression tag is written into durable event rows. Switching to suppress-at-write
    later loses evidence that cannot be recovered.

The proposed shape (Option A) is the researcher's verified recommendation:

  Table `maintenance_windows`: `id INTEGER PRIMARY KEY AUTOINCREMENT`, `port INTEGER NOT NULL`,
  `start_minute INTEGER NOT NULL CHECK (start_minute >= 0 AND start_minute < 1440)`,
  `duration_minutes INTEGER NOT NULL CHECK (duration_minutes >= 1)`, `weekdays TEXT NOT NULL`
  (comma-separated ISO weekday integers, Mon=1..Sun=7, matching the existing `service_meta.tags`
  CSV-in-TEXT convention), `grace_minutes INTEGER NOT NULL CHECK (grace_minutes >= 0)`,
  `enabled INTEGER NOT NULL DEFAULT 1`, `created_ts INTEGER NOT NULL`, `updated_ts INTEGER NOT NULL`;
  index `idx_maintenance_windows_port` on `(port, enabled)`. No FOREIGN KEY on `port` — no existing
  port-keyed table in this codebase declares one.

  Additive columns: `events.suppressed_reason TEXT`, `events.maintenance_grace_until INTEGER`,
  `events.down_since_ts INTEGER`, `services.overrun_raised_ts INTEGER`.

The undo cost if this is wrong: an operator's stored windows and every tagged event row already
written would need a migration to reshape, and `events` rows for outages already recorded cannot be
back-filled with information the old shape never captured.
  </context>
  <options>

      <pros>Matches D-03/D-05/D-10 exactly; every convention (CSV-in-TEXT weekdays, no FK, additive _add_column) is already established in this codebase; the frozen maintenance_grace_until column is what makes a mid-outage window edit non-retroactive.</pros>

3. `dashboard/beacon/maintenance.py` — new framework-free module importing only `dataclasses`,
   `datetime` and `zoneinfo`. It must import no database driver, no web framework, and nothing from
   the application edge module. Define:
   - module constant `MAINTENANCE_REASON` with the value `maintenance` — the single suppression tag
     literal every other module references rather than re-spelling.
   - `resolve_timezone(name)` returning a `ZoneInfo`, catching the zoneinfo lookup failure and any
     value error and returning the UTC zone instead. Fail closed and log nothing at import time.
   - `parse_weekdays(text)` returning a `frozenset` of ISO weekday integers Mon=1..Sun=7 parsed from
     a comma-separated string, returning an empty frozenset on any unparseable token. Standardize on
     ISO integers end to end (Pitfall 1) — never Python's `weekday()` zero-based value.
   - `format_weekdays(weekdays)` returning the canonical ascending comma-separated string.
   - frozen dataclass `Window` with fields `id`, `port`, `start_minute`, `duration_minutes`,
     `weekdays`, `grace_minutes`, `enabled`, validating in `__post_init__` in the style of
     `telemetry.py`'s `HistoricalRange`: integers that are not booleans, `start_minute` within
     0..1439, `duration_minutes` at least 1, `grace_minutes` at least 0, `weekdays` a non-empty
     subset of 1..7.
   - `window_from_row(row)` translating a sqlite row mapping into a `Window`, returning `None`
     instead of raising when the row is malformed — this is the fail-closed boundary that keeps a
     corrupt stored row from aborting the worker's write transaction.
   - `_local_occurrence_epochs(window, now_epoch, tz)` yielding every UTC epoch at which this window
     could have started within a bounded two-day lookback, honoring D-02: round-trip each candidate
     local wall time through its epoch and back and skip it when the wall time is not reproduced
     (the spring-forward gap), and yield both the fold-0 and fold-1 instants when they differ (the
     fall-back repeat). The lookback must be a named module constant, not an inline number.
   - `coverage(windows, now_epoch, tz_name)` returning a two-tuple of covered flag and frozen grace
     epoch or `None`. Skip disabled windows and rows that `window_from_row` rejected. A window
     covers when `start_epoch <= now_epoch < start_epoch + duration_minutes*60 + grace_minutes*60`.
     When several cover, return the maximum grace end (D-05 longest grace wins).
