# Phase 03.1 Plan 01: Planned Maintenance Recognition Tracer Summary

**DST-safe maintenance-window coverage (zoneinfo + PEP 495 fold) tags covered down/recovery transitions in the worker's single write transaction, skipping the alert path while writing every suppressed event as a retained, tagged row.**

## Accomplishments
- Migration 9 (`dashboard/beacon/migrations.py`): `maintenance_windows` table plus additive `events.suppressed_reason`/`maintenance_grace_until`/`down_since_ts` and `services.overrun_raised_ts` columns, registered as `Migration(9, 'planned_maintenance', True, ...)`, applying idempotently and additively over every existing migration fixture.
- New framework-free module `dashboard/beacon/maintenance.py`: `MAINTENANCE_REASON`, `resolve_timezone` (fails closed to UTC), `parse_weekdays`/`format_weekdays` (ISO Mon=1..Sun=7, CSV-in-TEXT), `Window` (frozen dataclass with `__post_init__` validation), `window_from_row` (fail-closed to `None` on any malformed row), and `coverage()` (DST-correct local wall-clock matching via round-trip epoch verification, longest-grace-wins on overlap).
- Suppression tagging shared by `worker_handle_state_transition` and `_legacy_handle_state_transition` via a single `_maintenance_suppression_decision` helper: a down transition asks `coverage()`; a recovery inherits its tag from the down period's own opening event row (D-08 non-inference) and never re-derives live coverage.
- The worker path reads windows, decides suppression, and writes the tagged `state_change` INSERT inside one `_worker_write_transaction` block (no nested `BEGIN IMMEDIATE`, per Pitfall 6); a suppressed transition returns before `worker_send_transition_alert` is ever called.
- `Settings.timezone` sourced from `TZ`, stripped, failing closed to `'UTC'` on empty or unresolvable zone names.
- `get_maintenance_windows`/`get_open_down_transition` repository reads, operating on the caller's connection with no transaction of their own.
- `/api/events` now publishes `suppressed_reason`, `maintenance_grace_until`, `down_since_ts` for both the with-since and without-since branches.
- New test module `tests/test_maintenance_windows.py`: all 18 tests named in the plan's behavior block (`CoverageTests` x8, `DstCoverageTests` x3, `MigrationNineTests` x2, `SuppressionTracerTests` x4, `ClockIsolationTests` x1), all passing.

## Decisions Made
- **Task 1's schema decision (pre-resolved, option-a):** documented in frontmatter above; implemented verbatim as migration 9.
- `coverage()` accepts raw repository-row dicts rather than pre-built `Window` objects, applying `window_from_row` internally per row — keeps the single fail-closed boundary in one function and matches the behavior spec's framing ("skip disabled windows and rows that `window_from_row` rejected").
- `parse_weekdays` fails the *entire* field closed to an empty `frozenset()` on any single unparseable token, rather than accepting a partial set — an empty weekday set then fails `Window.__post_init__`, so a partially-corrupt weekday string can never silently narrow to "whatever days happened to parse."
