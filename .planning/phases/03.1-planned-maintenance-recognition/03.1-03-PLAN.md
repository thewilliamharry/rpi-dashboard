<objective>
Expand the tracer outward to the operator's own configuration surface: make maintenance windows
creatable, editable, disableable, and removable through the single existing service-metadata write
route, and returnable on the read that the editor modal already awaits.

The tracer proved a window suppresses a restart. This plan is what lets a human put a window there.
It extends `PUT /api/service-meta/<int:port>` (D-01) rather than opening a second mutation boundary,
so the `/advanced` read-only posture that Phase 3 sealed across 46 blocking threats stays intact.

Purpose: satisfy MNT-01's four verbs — configure, edit, disable, remove — with server-side bounds on
every field, because the browser is not a trust boundary.

Output: `upsert_maintenance_windows`, the validated `maintenance_windows` payload field, windows on
the GET response, two new bounded `Settings` fields, and a migration-9 fixture regression.
</objective>

## Planner Assumptions

Adopted from `03.1-RESEARCH.md` on the researcher's recommendation and recorded here rather than
taken silently. None was separately ruled on by the operator; each is one line away from being
changed because every numeric one is a configurable setting rather than an inline literal.

| # | Assumption | Adopted as |
|---|-----------|-----------|
| A1 | Detector start tolerance 15 minutes, duration tolerance 10 minutes | `maintenance_start_tolerance_seconds` = 900, `maintenance_duration_tolerance_seconds` = 600 |
| A2 | Suggestion evidence lookback 21 days | `maintenance_suggestion_lookback_days` = 21 |
| A3 | Suggested weekday set defaults to all seven days; the operator narrows it via the Adjust path | `MAINTENANCE_SUGGESTION_WEEKDAYS` |
| A4 / Q4-7a | The covering boundary is frozen onto the down transition's own event row at suppression time; editing or disabling a window mid-outage does not retroactively change the committed down period, and a future down period picks up the edited window | `events.maintenance_grace_until` |
| A5 | Overrun detection folded into the existing down-only probe loop rather than a new worker callback | plan 03.1-04 task 2 |
| A6 | `tzdata` added as a pinned dependency plus a `TZ`-sourced `Settings.timezone` failing closed to UTC, with compose plumbing | plans 03.1-01 and 03.1-02 |
| Q3-7b | Suppressed transitions count as detector evidence, but the suggestion output is withheld when the detected cluster substantially overlaps an already-enabled window for that port | plan 03.1-06 |
| Planner | The per-service window cap and its operator-facing message are not covered by the UI-SPEC Copywriting Contract; the cap is a security backstop and its message is planner-authored | `maintenance_windows_per_port_max` = 50 |

**Edge-probe rows carried as explicit assumptions** (the two `unclassified` rows the probe could not
classify are manual-review nudges, surfaced here rather than dropped):

- **MNT-02 / unclassified** — planner assumption: the detector's boundary behaviour is exercised by
  explicit tests for exactly three versus two qualifying occurrences and for a cluster that straddles
  the configured start-tolerance boundary (`DetectorTests`, plan 03.1-06). Flagged for manual review.
- **MNT-04 / unclassified** — planner assumption: the overrun boundary behaviour is exercised by
  explicit tests at the frozen boundary and at the frozen boundary minus one second, plus repeated
  polls producing exactly one event (`OverrunTests`, plan 03.1-04). Flagged for manual review.

The remaining eight edge-probe rows (MNT-01 adjacency, empty, ordering, idempotency, concurrency;
MNT-03 adjacency, empty, ordering) are resolved into concrete acceptance criteria and appear as
`must_haves.truths` in plans 03.1-01 and 03.1-03.
