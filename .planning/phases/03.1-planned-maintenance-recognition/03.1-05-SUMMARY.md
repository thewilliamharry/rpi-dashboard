# Phase 03.1 Plan 05: Maintenance Window Editor UI Summary

**The operator now creates, edits, disables, and removes maintenance windows entirely inside the existing service metadata editor -- five plain controls per row (Start, Duration, Weekdays, Grace, Enabled) plus a two-step Remove, built from document-created DOM nodes and the existing design tokens, with zero-one-many counts, a bounded scrolling list, dimmed-not-hidden disabling, and verbatim server-rejection messages all reusing the single shared error region.**

## Accomplishments

- `dashboard/index.html`: an always-visible `.meta-maintenance` section inside `#meta-form`, placed after Tags and before the existing `Advanced` `<details>`. Stable hooks: `meta-suggestion` (reserved, hidden, for plan 03.1-06), `meta-window-count`, `meta-window-empty` (with the exact Copywriting Contract heading and body), `meta-window-list`, and `meta-window-add` (`.meta-btn .meta-btn-ghost`, matching `#meta-cancel`'s existing treatment so Save stays the section's only primary commit action). No second `#meta-error` region.
- `dashboard/style.css`: `.meta-modal-window` bounded to `min(86vh, 720px)` with `.meta-form` scrolling internally (`.meta-actions` stays the form's last element, unpinned, exactly as before); `.meta-window-list` scrolls past four rows at `max-height: 280px` (mirroring `.evidence-list`); `.meta-window-row` uses an `auto-fit`/`minmax(180px,1fr)` responsive grid (mirroring `.services-grid`); `.meta-weekday-chip` wraps rather than shrinking, with an accent-bordered `[aria-pressed="true"]` selected state; `.meta-window-row.is-disabled` dims labels/help/remove text to `var(--muted)` while every field stays focusable; `.meta-window-remove` is neutral (no destructive red); narrow-viewport (`<720px`) rules give every added control (time/number inputs, weekday chips, the Enabled label, Remove) a 44x44 hit target; light-theme counterparts added to the existing `html.light` block. No new CSS custom property.
- `dashboard/app.js`: `MAINTENANCE_WEEKDAYS` (Monday-first, ISO 1-7, abbreviation + full-day label); `renderMaintenanceWindows`/`addMaintenanceWindowRow`/`readMaintenanceWindows` build and read rows through `document.createElement`/`.value`/`.textContent` only (no `innerHTML`); two-step inline `Remove`→`Confirm remove` per row with no native `confirm()`; `openMetaEditor` opens synchronously on already-known fields, then `loadMaintenanceWindowsForEditor` fetches `GET /api/service-meta/<port>` and renders the maintenance section in one pass (no skeleton/spinner/partial state); `submitMetaEditor` adds `maintenance_windows: readMaintenanceWindows()` to the existing PUT payload and shows a server's `Window {n}: ...` message verbatim on rejection (generic copy otherwise), leaving the modal open with every row preserved; `+ Add window` wired to append a row prefilled with the default grace (15) and focus its Start field.
- `tests/test_ui_contract.py`: 3 new source-string tests -- the five stable ids present exactly once with one shared error region, the four owned Copywriting Contract strings verbatim, and the stylesheet's bounded-list/chip-wrap rules.
- `tests/test_ui_states.py`: `_service_meta`/`_maintenance_route` fixture helpers stubbing `GET`/`PUT /api/service-meta/<port>`, plus 10 named Playwright tests covering empty state, singular/plural count, add-row prefill+focus, weekday chip toggle+label, disable-dims-without-hiding, two-step remove, verbatim server validation with modal-open/rows-preserved, four-row scroll overflow, 44px narrow-viewport touch targets, and focus-trap reachability of the new controls.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `get_service_metadata`'s `SELECT m.port` returns NULL for a service with no `service_meta` row yet**
- **Found during:** Task 2, running the plan's required regression command (`uv run --project dashboard python -m pytest -q`)
- **Issue:** `tests/test_ui_safety_integration.py::test_stale_to_fresh_page_persists_actions_and_records_recovery` started failing with `PUT /api/service-meta/null 404` once `openMetaEditor` began fetching `GET /api/service-meta/<port>` and merging the full response into `editingService`. The repository's `LEFT JOIN service_meta m ON m.port = s.port` selects `m.port` (the joined table's column), which is `NULL` when the service has never had metadata saved -- a pre-existing bug in `dashboard/beacon/repositories.py`, newly exposed because this plan is the first caller to consume that field client-side.
- **Fix:** `loadMaintenanceWindowsForEditor` now reads only `meta.windows` from the GET response instead of spreading the entire payload into `editingService`, so the correct `service.port` (already known from the click handler) is never overwritten by the NULL. `dashboard/beacon/repositories.py` is owned by the parallel 03.1-04 plan and out of scope for this plan's `files_modified`, so the fix lives entirely in `dashboard/app.js`.
- **Files modified:** `dashboard/app.js`
- **Verification:** `uv run --project dashboard python -m pytest -q tests/test_ui_safety_integration.py` passes; full suite green (380 passed, 454 subtests, 0 failed).
- **Committed in:** `7e5d748` (Task 2 commit)

**2. [Rule 1 - Bug] The Enabled checkbox's clickable label lacked a narrow-viewport `min-width`**
- **Found during:** Task 3, writing `test_every_added_control_meets_the_narrow_viewport_touch_target`
- **Issue:** `.meta-window-row .meta-checkbox` had `min-height: 44px` but no `min-width`, so its clickable area (the `<label>` wrapping the checkbox and its text, which is the real hit target since clicking a label toggles its input) could measure narrower than 44px at `<720px` viewports, short of the plan's must-have "every interactive control this section adds keeps a minimum 44 by 44 pixel hit target."
- **Fix:** Added `min-width: 44px` alongside the existing `min-height: 44px` in the same narrow-viewport rule.
- **Files modified:** `dashboard/style.css`
- **Verification:** `test_every_added_control_meets_the_narrow_viewport_touch_target` passes, asserting `.meta-checkbox`'s bounding box is at least 44x44.
- **Committed in:** `e482e72` (Task 3 commit)
