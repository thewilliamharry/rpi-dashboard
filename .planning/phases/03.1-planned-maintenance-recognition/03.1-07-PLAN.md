<objective>
Expand outward to the truth-telling half of MNT-03: publish, on both read surfaces, that a service
is offline *and* expected — without softening the availability figure, without dropping it from the
failure surface, and without letting the global exception summary claim an actionable problem.

There is exactly one definition of "covered" in this phase: the same pure `coverage` function the
suppression write path calls. This plan calls it a second time, at read time, so the displayed state
and the stored tag can never disagree. Attribution rides alongside the untouched uptime computation
rather than inside it, because D-09 permits exactly one availability number and it is always true.

Purpose: give the browser truthful derived fields to render, and keep the exception projection a
pure projection.

Output: the attribution intersector, the two bulk repository reads, the derived availability value
and evidence block on the advanced snapshot, the same derivation on the services list route, and
regressions proving the uptime arithmetic did not move.
</objective>
