# Phase 03.1 Plan 09: Main-Dashboard Maintenance Presentation Summary

**The dashboard service card now shows a calm, static, disclosed `MAINTENANCE` state instead of the fading offline treatment while a window covers it; the events feed hides expected transitions behind a control that states their exact count and tags them `Expected` once revealed; and the overrun outage renders at full, unmuted severity with two separate timestamps and no pill.**

## Performance

- **Duration:** ~50 min
- **Tasks:** 3
- **Files modified:** 4 (0 created)

## Accomplishments

- `dashboard/app.js`: `serviceCardAvailability()` -- a fail-closed helper reading the server's `availability` field, falling back to the true `is_online` classification for anything but the literal `'maintenance'` value. `buildServiceCard` swaps to `svc-card svc-maintenance` (never `svc-card offline`) and gives the status element a new `svc-maintenance-status` class, the `MAINTENANCE` word, a static (non-animating) pip, and a `title` attribute disclosing the derivation with a local coverage-end time via the new `fmtLocalDateTime()` helper -- the `svc-since` line's content is untouched.
- `dashboard/app.js`: `renderEvents` now splits type-visible events into suppressed/unsuppressed via `suppressed_reason` (never dropping suppressed rows from the fetched array), renders a full-width `evt-reveal` control only when at least one suppressed entry is loaded (stating the exact singular/plural hidden count, flipping to `Hide suppressed entries` when activated, not persisted across reload), and gives each revealed suppressed row an `evt-pill-expected` badge after its title while keeping its existing event-specific colour class. The `maintenance_overrun` event type joins the visible set and is unconditionally excluded from the suppressed partition; its entry renders the contracted title and two independent `Down since` / `Raised at` lines using the ordinary `evt-down` treatment, with no pill.
- `dashboard/style.css`: `.svc-status-row` gains a defensive `flex-wrap: wrap`; new `.svc-maintenance-status` rules (dark + light) reuse `--accent3` with no motion declaration; new `.evt-reveal` (ordinary button vocabulary, no maintenance token) and `.evt-pill`/`.evt-pill-expected` (`--accent3`) rules, plus the narrow-viewport 44px hit target for the reveal control. No new custom property introduced anywhere.
- `tests/test_ui_contract.py`: two new source-string/stylesheet tests pinning the `MAINTENANCE` word, the three reveal-control strings, the `Expected` pill text, the overrun title/detail templates, and the five new CSS class declarations plus the status-row wrap rule.
- `tests/test_ui_states.py`: 19 new live-DOM tests (17 named in the plan's behavior block plus 2 extra: an ordinary-width non-wrap check and a dedicated singular/plural/absent split) covering the calm card, its reversion, the reveal control's full lifecycle including a failed-refresh survival case, the revealed-row colour/pill combination, and the overrun entry's severity and timestamp separation, plus the maintenance-colour interactive-element exclusion.
