## Decisions Made

- Split the detector's cross-module import resolution and module-local factory lookup into two independently deletable code paths (rather than one shared `factories`-dict lookup) so each of the plan's four seam-resolution clauses is provably, individually pinned by its own fixture — collapsing them would have let one deletion silently take out two clauses at once, defeating the deletion-resistance requirement.
- `create_verified_backup`'s three connections and the three read-only `recovery.py` sites use bare `contextlib.closing` since none perform explicit multi-statement writes needing the stdlib connection's implicit commit/rollback. `_apply_pending_migrations`' apply connection keeps `close outermost, transaction innermost` (`with closing(sqlite3.connect(...)) as conn: with conn: ...`) so an implicit rollback-on-exception still runs before the connection closes — pinned by the three named migration rollback regressions passing unmodified.
- `worker_process_preview_requests` binds through `database_access`, the closing seam already imported in both of `app.py`'s beacon import branches (try/except for direct-module gunicorn imports), requiring no import changes.
