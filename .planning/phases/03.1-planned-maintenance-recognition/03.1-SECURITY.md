## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Browser → `PUT /api/service-meta/<int:port>` | The only mutation surface this phase extends. Guarded by `enforce_request_security` (trusted-host, `X-Beacon-UI`, same-origin) before the structured window list is parsed. | Operator-authored maintenance window array (untrusted JSON) |
| SQLite row → worker transition funnel | Stored window rows are untrusted input to the worker's safety-critical write transaction; a malformed row must not raise. | Persisted window rows of unknown quality |
| Environment (`TZ`) → worker clock | An operator-supplied zone name reaches `zoneinfo` and may be unresolvable. | IANA zone name (operator-supplied) |
| PyPI → build environment | A third-party package (`tzdata`) enters the container image. | Package sdist + wheel |
| Worker write transaction → `events` table | The suppression tag written here is durable evidence Phase 4 consumes; it must not be re-derivable or overwritable. | Suppression reason + frozen grace boundary |
| Stored event row → overrun evaluator | The frozen boundary on the down period's own event row is the sole authority for when an overrun is due; live configuration is never consulted. | `maintenance_grace_until` (frozen at suppression time) |
| Worker write transaction → outbound webhook | The alert effect leaves the process; it must not hold a write transaction open while it does. | Alert payload |
| Server JSON → browser DOM | Window values, service names, event details, evidence sentences, and server error strings are rendered into the operator's page. | Server-derived strings (potentially attacker-influenced) |
| Stored `events` rows → detector | Historical rows of unknown quality feed a read-time computation running inside a web request. | Outage observation pairs |
| Detector output → operator | The proposal is advisory only and must not be mistaken for configuration. | Suggested window (start minute, duration) |
| Read composition → browser | The derived availability value is a published vocabulary both browsers bind to. | `MAINTENANCE_AVAILABILITY` state token |
| `migrate` one-shot → `web` / `worker` | Schema upgrade must complete before either long-lived service takes a shared maintenance lease. | Database schema version + maintenance lease |
| Flask request thread → SQLite | Window replacement writes inside the process-wide `_db_lock` shared with every other web write. | Write transaction |

## Open Threats

### Blocking (severity ≥ `high`)

**T-03.1-94** — Spoofing · high · plan 17 · disposition `mitigate`

*Threat:* A "circular" comparison applied to duration as well as start minute, making a five-minute restart and a near-day-long outage look ten minutes apart and clustering unrelated failures into a maintenance proposal.

*Declared mitigation:* "Duration stays a plain magnitude comparison in both the detector and the withholding rule; pinned by a dedicated test in each and by a source assertion naming the lines."

*Why it is open:* The **detector-side pin is vacuous**. The auditor applied the exact defect shape — routing duration through `_circular_minute_distance` at both sites — to a scratchpad copy and ran the named tests' inputs. `test_durations_are_compared_as_magnitudes_not_clock_positions` (tests/test_maintenance_windows.py:340) returns `None` under **both** the shipped and the perturbed code: its chosen fixture durations (5 min vs 1430 min) sit 15 circular minutes apart, outside the 600 s tolerance, so the test cannot fail against the defect it names. The withholding-rule twin (tests/test_maintenance_windows.py:425) **is** a valid discriminator (shipped `False`, perturbed `True`). Separately, the **declared source assertion is absent** — no source-reading assertion over `dashboard/beacon/maintenance.py` exists in the test file.

*Severity qualifier:* The **runtime code is correct today**. `dashboard/beacon/maintenance.py:296` (`abs(o['duration_seconds'] - anchor['duration_seconds'])`) and `:354` (`abs(window.duration_minutes - suggestion_duration)`) are both plain magnitude comparisons, and `_circular_minute_distance` is called at only two sites (`:295`, `:352`), both on start minutes. This is a **regression-gate gap, not a live vulnerability**. It is recorded OPEN rather than closed because it is a reproduced instance of exactly the failure class this phase registered five separate threats against (T-03.1-73, -86, -91, -97, -104): a gate that passes without ever having been capable of failing.

*Closure path (either is sufficient):*
1. Change the detector fixture's second duration at tests/test_maintenance_windows.py:340 from **1430 to 1435 minutes** — circular distance becomes 10 min, inside the 600 s tolerance, so a circular-duration regression would cluster and turn the `assertIsNone` red; or
2. Add the declared source assertion naming `dashboard/beacon/maintenance.py:296` and `:354` as plain magnitude comparisons.

Then re-run `/gsd-secure-phase 03.1`.
