<objective>
Close the phase with the thing that makes it an investigation rather than six separate charts:
one shared time axis carrying neutral incident markers, and a hover cursor that reads every
stacked chart at the same instant — presenting observed evidence without ever asserting a cause.

Purpose: D-17 gives markers as the persistent "when did things happen" and the cursor as "what
was true at that moment". Neither asserts a relationship; alignment is the reader's inference
from evidence Beacon actually observed. DIA-07 is satisfied by what the UI refuses to say as much
as by what it shows.
Output: the incident marker rail with cluster degradation; the cross-chart hover cursor and its
shared readout; the no-causal-language gate over every Phase 4 surface.
</objective>

  <action>
Give the operator one instant, read across everything at once.

`CURSOR_TARGET_IDS` names every element the cursor spans: the four host charts, the service state
band and the service latency chart. `history-time-cursor` is a single vertical line element
positioned across the whole stack — one element, not one per chart, so a single transform moves
it everywhere.

`moveTimeCursor(clientX)` is bound to `pointermove` over the stack and coalesces every event
through `requestAnimationFrame`, exactly as plan 04-03's tooltip path already does. Inside the
frame callback it does two things and nothing else: set the cursor line's transform, and write
`readoutForInstant(ts)` into `history-cursor-readout`. Chart `<path>` `d` attributes, band
segments, strip segments and marker positions are never regenerated in response to a pointer
event — recomputing six series per frame is the single largest Pi-performance hazard in this
phase (R-01).

`readoutForInstant(ts)` composes one panel from data already in hand: the instant in local time,
each host metric's value at the nearest bucket that actually contains that instant, the service's
band state and latency at that instant. A metric whose bucket at that instant is not observed
reads as the absence string, never as a nearby value silently borrowed from an adjacent bucket —
the readout describes the instant, not the nearest thing to it.

The readout describes co-occurrence and nothing more. Where it summarises two metrics together it
uses the co-occurrence phrasing pattern the Copywriting Contract fixes, of the form
`{Metric A} rose while {Metric B} was elevated in this window` — a statement about time, not
about mechanism.

`hideTimeCursor()` clears the line and the readout on `pointerleave` and on Escape. The cursor is
suppressed entirely while any chart in the stack is still loading (`correlationReady()` is false),
so a cursor readout is never composed against a skeleton, and it does not interfere with an
in-progress drag-select from plan 04-05 — the drag overlay takes precedence while a drag is
active.

The cursor line and its readout use the accent token, per the UI-SPEC's explicit accent
reservation for this phase's interactive investigation controls.

Tests: moving the pointer across the stack positions one `#history-time-cursor` element and
writes a readout naming the instant in the server-configured timezone and one value per host
metric; across at least ten pointer-move events, every chart path `d` attribute, every band
segment and every marker position is unchanged while the readout text changes; an instant falling
inside a non-`observed` interval reads as the absence string for that metric rather than an
adjacent bucket's value; the cursor is absent while any chart is loading; Escape and pointer-leave
both clear it; a drag in progress suppresses the cursor.
