## Planner assumptions surfaced (not silently taken)

1. **The copy is the reviewer's own suggested shape, taken verbatim rather than re-worded.**
   `04-VERIFICATION.md`'s `missing:` entry and `04-REVIEW.md`'s WR-01 Fix both give
   `"N of ? incidents (total unavailable)"` as the example. A longer in-voice alternative
   (`{N} of ? incidents — Beacon could not load the unfiltered total for this range.`) was
   considered and rejected: the element is a compact `aria-live="polite"` line that is announced on
   every filter change, and the traceable choice is the one the gap's own text names. Recorded so a
   later phase can widen it deliberately rather than discovering it was invented here.
2. **A `null` total, not a sentinel or a `0`.** `0` is a real, meaningful count in this element
   (`test_zero_match_incidents_renders_empty_copy_and_matching_count` asserts `0 of 1 incidents`),
   so the absent value must be type-distinguishable from it. This follows the phase's own
   type-based absent-value rule rather than a magic number.
3. **`data-total-known` is added, not just the text.** It gives the regression a state assertion
   that does not depend on copy wording, and gives Phase 5 a styling hook for the uncertainty state
   without a DOM addition. `dataset` is already this file's idiom (`button.dataset.section`).
4. **No retry.** 04-REVIEW.md offers "or retry the baseline fetch once before falling back". A retry
   is not planned: it adds a load-amplification path on a failing server and does not close the gap
   (a second failure still needs an honest render). Disclosure is the whole fix.
5. **`beginIncidentsLoadingState` is left alone** — see the Scope fence.
