<objective>
Turn "theme parity" from a claim into an enumerated, self-maintaining contract.

One source-level test derives every theme-gated visibility rule from the stylesheets at test time,
asserts the set is exactly the eight known rules with their recorded classification, and asserts
the advanced workspace has none at all. One browser test asserts everything the contract calls
shared is genuinely present and displayed in both themes on the main dashboard. A third asserts
each deliberately-calm omission is hidden rather than absent, and names where the same fact is
still reachable in light mode.

Purpose: `05-RESEARCH.md` Pitfall 1 — the token system's completeness creates a false impression
that theming is done, while the real capability risk lives in scattered visibility overrides that
nothing enumerates. After this plan, a ninth such rule cannot land silently.
Output: `THEME_HIDDEN_RULES` and its three tests in `tests/test_ui_contract.py`; the dual-theme
main-dashboard parity and deliberate-calm tests in `tests/test_ui_states.py`.
</objective>

## Explicit assumptions recorded by this plan

- **A-12 — D-03's calmer reading of UX-01 is adopted, explicitly.** UX-01's wording ("compact
  analytics and history previews on the main dashboard in both light and dark themes") admits a
  stricter reading in which light mode must show the previews. This phase adopts D-03's calmer
  reading: on the main dashboard the arc gauges satisfy UX-01, and the five deliberate-calm
  omissions stay hidden in light mode. A later verifier should evaluate the phase against this
  recorded decision rather than re-deriving the requirement.
- **A-13 — `.svc-uptime-pct` is deliberate calm, extending D-03.** Not named in D-03; classified
  here by the identical rationale the UI-SPEC applies — it is a numeric analytics-history preview,
  not the core online/offline fact, which stays visible in both themes.
- **A-14 — `.corner` and `.offline-badge` are dead rules, not decorative omissions.** The audit
  found no element carrying either class is rendered by any document or script, so these two rules
  hide nothing in either theme. They are pinned as dead rather than deleted: deleting them is not
  this phase's job, and pinning them means a future phase that starts rendering either class must
  re-classify it before its markup can land.
- **A-15 — `.svc-preview` is the one accepted exception with no light-mode substitute.** Every
  other deliberately-calm omission has a named place the same fact is still reachable in light
  mode. The thumbnail image does not — thumbnails exist only on the main dashboard. D-03 accepts
  this. The preview *status* text (`.svc-preview-status`) is a separate class and stays visible in
  both themes, so light mode still reports preview capture state, and that is asserted.
- **A-16 — the inventory is derived, not transcribed.** The test extracts the rules from the
  stylesheet with a regex at run time and compares against a recorded classification table. A
  hand-copied list would go stale silently; a derived one fails the moment the stylesheet grows a
  ninth rule.
- **A-17 — Open Question 2 (05-CONTEXT) is resolved in plan 05-04, not here.** The uptime strip's
  per-segment accessible name is an accessibility question, not a theme-parity one; this plan
  asserts only that the strip and its segments render in both themes.
