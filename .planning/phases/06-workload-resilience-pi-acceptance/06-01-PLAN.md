<objective>
Move Beacon's preview thumbnail blobs off the primary `services` telemetry table into a dedicated
`thumbnails` table, proven end-to-end: the worker writes a capture into the new store, the web tier
serves those exact bytes, and the dashboard's `has_thumb` signal is derived from the new store.

Purpose: `services` is the row every scheduled sampling job (J3, J4, J5, discovery) reads and writes
for basic online/offline state. A 2 MiB BLOB column on that row is exactly the "large preview blobs
on the primary telemetry path" OPS-03 forbids. This plan is the tracer slice for the phase — it
crosses schema, repository, worker write path, web read path, and worker-ownership contract in one
end-to-end path.

Output: migration 10, `ThumbnailStoreRepository`, relocated read/write paths, the eight existing test
sites realigned onto the new store so the tracer commits against a green suite, the new
`tests/test_workload_resilience.py` suite file seeded with its first end-to-end test, and the phase's
measured full-suite runtime recorded in `06-VALIDATION.md`.
</objective>

  <context>
This is a one-way door. Once the migration commits on the Pi, the only way back to the previous
on-disk shape is restoring the verified backup `create_verified_backup` writes to
`/data/backups/dashboard-*-pre-v10.db` immediately before the migration runs (`migrations.py:602-620`,
`_apply_pending_migrations` at `migrations.py:709-716`). There is no down-migration in this codebase
— `MIGRATIONS` is forward-only and `schema_migrations` records applied versions, never reversals.

What is NOT at risk: the blobs themselves. The backfill INSERT and the emptying UPDATE run inside the
same `BEGIN IMMEDIATE` transaction, so a failure at any point rolls both back and leaves
`services.thumb_data` untouched. What IS at risk: an operator who later needs the previous schema
shape must restore the pre-v10 backup, losing everything written after the upgrade.

The alternative — leaving the blobs on `services` and dual-writing — does not satisfy OPS-03, whose
whole subject is "without placing large preview blobs in the primary telemetry path."
  </context>
