<objective>
Give preview capture the one thing it is missing: a bounded retry with real backoff that ends in a
distinct, operator-visible degraded state instead of a silent 24-hour wait for the next discovery
cycle.

Purpose: `06-RESEARCH.md` confirms the single-owner browser, the ~27s capture deadline and the
serializing semaphore already exist and are correct. What does not exist is (a) any code that reads
`preview_requests.attempt_count` as a cap — it is incremented on every claim and never enforced
(`queues.py:657`, RESEARCH Pitfall 2) — and (b) any UI that distinguishes "capture keeps failing"
from "never captured" (`app.js:229-237` renders one generic fallback for both).

Output: `PREVIEW_STATUS_DEGRADED`, a backoff-aware claim, the three D-02 retry settings, and a
degraded state rendered in both themes.
</objective>

**The D-02 values and why (record this rationale in the code comments, not only here).** No code
precedent fixes these numbers — `THUMB_REFRESH_DAYS = 1` is a refresh cadence, not a retry policy —
so they are chosen here and made configurable:
- `PREVIEW_MAX_ATTEMPTS = 3` (one initial attempt plus two retries). The capture deadline is
  `PREVIEW_BROWSER_BUDGET_MS = 27_000` on a single-thread `screenshots` executor, so three attempts
  bound one request's worst-case browser occupancy at roughly 81 seconds. That is small against the
  request's own 1800-second `deadline_ts` (`_enqueue_preview_in_transaction` sets `now + 1800`) and
  leaves the lane free for other ports across the 2-second J6 poll.
- `PREVIEW_RETRY_BASE_SECONDS = 60`, `PREVIEW_RETRY_MAX_SECONDS = 600`, doubling per attempt. This is
  the same exponential-with-cap shape as `telemetry_retry_base_seconds` / `telemetry_retry_max_seconds`,
  scaled down because a preview is cheaper and far more visible to the operator than a telemetry
  rollup. With three attempts the total backoff is 60 + 120 = 180 seconds, so the whole retry
  sequence — backoff plus captures — finishes well inside the 1800-second deadline and cannot be
  silently cut short by `expire_preview_requests`. The 600-second cap only binds if an operator
  raises `PREVIEW_MAX_ATTEMPTS`.
