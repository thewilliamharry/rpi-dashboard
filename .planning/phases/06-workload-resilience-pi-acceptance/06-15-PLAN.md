<objective>
Instrument `_db_lock` so that wait time and hold time are measured per route and per
acquisition, and can be read out of a running container over HTTP. This is the tracer for the
round-4 diagnostic: the thinnest path that touches every layer the diagnostic needs — env flag,
lock object, collector, Flask request plumbing, readout endpoint — wired end to end and proven
with a real request before anything else is built on it.

reduced. `06-CONTEXT.md` D-01's fence holds and `PROH-OPS-04-02` holds: the 28 `with _db_lock`
call sites in `dashboard/app.py` end this plan byte-identical to how they started. The only
`_db_lock` line that changes is its declaration at `dashboard/app.py:127`, and Task 3 both proves
that change preserves mutual exclusion and re-closes `06-SECURITY.md`'s `T-06-24` on new evidence.
(`06-CONTEXT.md`'s other decision, D-02 — the preview retry budget and thumbnail TTL knobs — was
implemented by `06-01` through `06-03` and is untouched here; see the source audit at the end of
this plan.)

measurement that converts the `_db_lock` attribution from strong inference into direct evidence, or
refutes it. `06-DEBT.md` `D-DEBT-06-09` records that two consecutive rounds proposed a mechanism and
were partly wrong. This plan builds the instrument that can say which.

Output: `dashboard/beacon/lockprofile.py`, a diagnostic readout endpoint that 404s by default, and

<plan_review_against_d_debt_06_10>

`D-DEBT-06-10` requires this round's planning to review every clause that mandates a **mechanism**
rather than an **outcome**, to say why where a mechanism is genuinely required, and to name what
would make that mechanism wrong. This section records that review for this plan.

**Clauses that state an outcome (the default, and the majority):** every entry in `must_haves.truths`
and every `<acceptance_criteria>` bullet below is phrased as an observable consequence — a number a
reader would act on, a status code, an equality between two measured totals, an observed count of
overlapping critical-section entries. None of them can be satisfied by a wrapper that merely exists.

**Clauses that genuinely mandate a mechanism, with reasons and falsifiers:**

1. **"Wrap the lock object at its declaration, not the 28 `with _db_lock` call sites."**
   *Why a mechanism is required:* the alternative — replacing each `with _db_lock` with a
   contextmanager call — edits 28 lines that `06-CONTEXT.md` D-01, `PROH-OPS-04-02` and
   `06-SECURITY.md` `T-06-24` all fence, and `tests/test_incidents_api.py:251` asserts the exact
   call-site text of. The outcome (per-route wait/hold numbers) is reachable either way; only one
   way preserves the fence. *What would make this mechanism wrong:* if wrapping the object failed
   to preserve mutual exclusion, or if any call site used the lock in a way a wrapper cannot
   support (a non-`with` `acquire()`, a `try`/`finally` release, an `RLock` reentrancy assumption).
   Task 3's no-overlap test and call-site inventory are the guards that would catch this; they
   assert observed behaviour and observed text, not the wrapper's presence.

2. **"Attribute by `request.url_rule.rule`, not by `request.path`."**
   *Why a mechanism is required:* the outcome ("bounded memory under a 600s run") is not by itself
   enough to pick a key, and `/api/thumbnail/<port>` would otherwise mint one route bucket per
   discovered port. *What would make it wrong:* if `url_rule` were `None` for a route the load
   generator exercises, that route's acquisitions would silently land in the no-request bucket and
   the per-route attribution would be incomplete. The guard is the summing identity in Task 1's
   acceptance criteria plus an explicit assertion that every route the harness exercises appears as
   its own key — an outcome, checked against a named list.

3. **"The readout endpoint returns 404 when the flag is off."**
   *Why a mechanism is required:* the outcome is "no diagnostic surface in production"; 404 rather
   than 403/empty-200 is chosen because `/metrics` at `dashboard/app.py:3275-3277` already
   establishes exactly this shape for exactly this reason, and a second, different shape for the
   same concern is a maintenance trap. *What would make it wrong:* nothing about the number 404 is
   load-bearing; if a future reviewer prefers 403 the outcome is unchanged. Flagged so a later
   reader knows this clause is convention, not requirement.

**Guards assert consequence, not shape.** No acceptance criterion in this plan is satisfied by "a
wrapper exists", "a field is present", or "a call returns 200". The inertness criterion is not "the
hook checks a flag" but "the collector's timing entry point is called zero times across N real
requests". The accuracy criterion is not "hold_ns is recorded" but "a critical section held for a
known duration reports a hold within a stated tolerance of that duration". The mutual-exclusion
criterion is not "the wrapper delegates to a Lock" but "zero overlapping entries observed across
N threads".

**Every new test is mutation-verified** — run against the pre-change code (or against a
deliberately broken variant of the new code) and observed to FAIL, with the observed failure values
recorded in the SUMMARY. `06-13`'s round did this (`90.0 != 100.0`; wrong `Window` at iteration 1;
`0 != 1` primes); this round matches it. Each task below names its own mutation.

**What this review changed.** Three things, recorded so the review is visible rather than claimed:
(a) the first draft of Task 1 said "`/api/services` must report a non-zero hold time" — satisfiable
by a wrapper that records garbage; it now requires the recorded hold to match a *known* critical
section duration within a stated tolerance. (b) The first draft of Task 2's inertness check asserted
that `_db_lock` is an instance of `threading.Lock` when disabled — a shape assertion; it is now a
call-count assertion on the module's own timing entry point, which is falsifiable by any code path
that does timing work. (c) The first draft mandated "the collector must be bounded" without naming a
consequence; it now requires a specific overflow behaviour with a visible `route_overflow` flag, so
a reader can tell truncation from absence.

    Create `dashboard/beacon/lockprofile.py` importing only `dataclasses`, `threading` and `time`
    from the stdlib and nothing from the `beacon` package.

    Define `_timer_ns()` as the module's single timing entry point, returning
    `time.monotonic_ns()`. Every timestamp in this module goes through it, so Task 2 can count
    calls to it and prove the disabled path performs no timing work. Define
    `SNAPSHOT_SCHEMA_VERSION = 1`, `ENABLED = False`, `MAX_TRACKED_ROUTES = 64`,
    `OVERFLOW_ROUTE_LABEL = '&lt;overflow&gt;'`, `NO_REQUEST_ROUTE_LABEL = '&lt;no-request&gt;'`, and two
    fixed tuples of log-spaced upper edges in nanoseconds — `WAIT_HISTOGRAM_EDGES_NS` and
    `HOLD_HISTOGRAM_EDGES_NS` — spanning roughly 10 microseconds to 10 seconds in about twenty
    buckets, with one implicit overflow bucket above the last edge. Fixed edges, not a growing
    sample list: they make the collector's memory a constant independent of run duration, and they
    let `06-17` derive percentiles by subtracting two cumulative snapshots without needing a reset.

    Define `RouteStats` as a dataclass holding `acquisitions`, `wait_ns_total`, `hold_ns_total`,
    `wait_ns_max`, `hold_ns_max`, and two lists of bucket counts sized to the edge tuples.

    Define `LockProfileCollector` owning a `threading.Lock` of its own (named distinctly so it is
    never confused with `_db_lock`), a `dict` of label to `RouteStats`, a global `RouteStats`-shaped
    total, and a `route_overflow` bool. `record_acquisition(route_label, wait_ns, hold_ns)` adds to
    both the per-route entry and the global total under the collector's own lock; when the route
    table already holds `MAX_TRACKED_ROUTES` distinct labels and the incoming label is new, it
    records under `OVERFLOW_ROUTE_LABEL` and sets `route_overflow`. `snapshot()` returns a plain
    nested dict of ints and bools — JSON-serializable with no custom encoder. `reset()` returns the
    collector to its initial state and exists for tests only.

    Define `InstrumentedLock` holding the wrapped `threading.Lock` as `raw`. `__enter__` reads
    `_timer_ns()`, acquires `raw`, reads `_timer_ns()` again, stores the acquisition timestamp and
