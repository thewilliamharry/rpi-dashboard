<objective>
Measure option C on the hardware that gates it — cheaply first, then for the record.

**Two segments, one Pi session, one build, with a stop between them.**

*Segment A* is the guard this phase has never had. `tests/services_route_profile.py` seeds its own
temporary database and measures `/api/services` in-process; it runs in minutes and needs no
deployment. Run on the Pi at the pre-`06-25` parent commit and at HEAD, it answers the one question
that decides whether a ten-minute acceptance run is worth taking: **did per-request cost actually
fall on this hardware?** Round 5 did not ask it, landed two changes, ran the 600-second pass, and
measured `/api/services` **68.4% worse** — a full round and a revert (`ea8689e`) for a fact a
two-minute measurement would have shown. `PROH-OPS-07-20` makes not asking it a recorded error.

*Segment B* is the gating acceptance run: uninstrumented, `run_kind acceptance`, `--concurrency 3
--duration 600`, every declared route budget unchanged, per criterion 5 as amended by
`D-DEBT-06-20`. It runs only if segment A clears.

**What the run is measured against.** `/api/services` has now missed twice at concurrency 3 on
independent runs — 635.6ms p95 (`06-ACCEPTANCE-C3.md`, confounded) and 679.3ms p95
(`06-ACCEPTANCE-C3-RUN2.md`, clean) against a 500ms budget. Run 2's confound was resolved and was
not the explanation; the route degraded rather than improved. The shortfall to close is **179.3ms**,
and the record must state the third run's figure next to both, together with the `service_checks`
row count, because `D-DEBT-06-14` is the entry in this phase's own debt register created by
comparing an absolute figure across a dataset that had grown 2.24x.

**What this plan may not do.** It may not promote OPS-07 (`PROH-OPS-07-08`) — that belongs to an
independent verification round, following the `TEL-06` precedent. It may not touch a budget, a
threshold or a limit in response to what it measures (`PROH-OPS-07-01`, `PROH-OPS-07-10`). And it may
not decide option A: if C lands and the route still misses, option A is a one-way roadmap decision
that belongs in front of the user with its own blocking `checkpoint:decision` in a follow-up round,
not inside a measurement plan.

Purpose: produce the hardware evidence OPS-07 will eventually close on, honestly, either way.
Output: a Pi-class cost verdict, an admissible acceptance report, and a runbook that stops the next
round rediscovering the command path.
</objective>
