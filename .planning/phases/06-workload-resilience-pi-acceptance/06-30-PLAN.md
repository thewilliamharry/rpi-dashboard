<objective>
Record what this round found out, decide what to do about it, and leave nothing implicit.

Three things happened that a code commit cannot carry.

**One: an executed, merged, pushed plan has an acceptance criterion that was never implemented.**
`06-25-PLAN.md` lines 508-522 required a test reading the `UPTIME_STRIP_QUERY` constant's value and
asserting no division character and no rounding call appear in it. `grep -rn "UPTIME_STRIP_QUERY"
tests/` returns nothing at `9da5e5e` and still returns nothing at `761f68a`. `06-25-SUMMARY.md`
reports three of three tasks complete, `status: complete`, `Self-Check: PASSED`, and does not
mention the omission. The dynamic half of that criterion's intent did work — mutation (c) injected a
SQLite rounding call into the query and the 400-trial differential caught it at trial 33, port
40331, `0.063` against the correct `0.062` near one sixteenth — so the hazard is real and was
demonstrated. What was missing was the standing regression guard, for the whole interval between
`d127158` and `06-29`. That is recorded against `06-25`, not quietly absorbed here.

**Two: the criterion as written would have forbidden the correct fix.** Bucket-index arithmetic
needs integer division, so a blanket ban on the division character fails on any correct
implementation of `06-29`'s reshape. `06-29` narrowed the guard. Narrowing a guard so that code can
pass it is precisely the move `PROH-OPS-07-01` and `PROH-OPS-07-10` exist to forbid, and this
phase's record has been damaged by that pattern before. So the narrowing gets a reasoned, standing
record that states the distinction it turns on — the original conflated *no SQLite rounding of a
rendered value* with *no division character anywhere in the query text*, and the second is an
over-broad proxy for the first — together with the proof that the narrowed form still fails the
mutation it exists for, in the same commit that narrowed it.

**Three: the fix may not have cleared its bar.** `06-29` pre-registered a projection of ~70ms
against a 56.820ms pass condition, and a projected verdict of FAIL. Whatever `06-PROFILE-4.md`
actually says, the choice between keeping the reshape and reverting `/api/services`' wiring to the
Python sweep is the operator's, not the planner's, because reverting costs a fourth
`06-LOCK-AUDIT.md` realignment and a second scope-pin rewrite and leaves a proven-correct reader
unused in the tree.

And one thing this round must not do: leave `06-27` and `06-28` describing a build that no longer
exists. The append contract forbids editing either PLAN, so the amendments each needs are enumerated
here instead.

Purpose: put the round's non-code findings somewhere they survive, and let the operator decide.
Output: `06-GUARD-DECISION.md`, three `06-DEBT.md` entries, and a recorded decision.
