### A defect the audit chain found and closed

`/gsd-secure-phase 01` found a live bug in `dashboard/app.py`. `_legacy_screenshot_service` acquired `_screenshot_sem` (a `Semaphore(1)`) above a `try` whose `except OutboundPolicyError: return` sat between the acquisition and the `finally` that releases it — that `finally` belonged to a later `try`. One refused preview target permanently wedged every subsequent preview in the process.

It escalated past its own medium severity: a wedged J6 preview job blocks inside `admission.admit('preview')`, a block is not an exception so `admit()`'s `finally` never runs, and `WorkerAdmission.drain()` is an untimed `Condition.wait()` called *before* `shutdown_browser()` and `release_worker_lease()` — so the worker could neither shut down nor hand off, while J1's heartbeat kept renewing the lease. That is the named outcome of T-01-111, a **high**-severity threat.

Reachability was not exotic: a configured hostname alias passes `_normalize_service_url`, then `policy.plan` raises on `resolution_failed` (transient LAN/mDNS failure) or `resolved_address_not_allowed` — the rebinding answer T-01-31 exists to catch. The control that closes one threat was the trigger for another.

Fixed in `986187e` at the class level (the acquisition now sits below the planning block so no path can return between it and its `finally`), pinned by two regression tests confirmed red against the unfixed tree, and re-checked here: the fix does not disturb the Phase 1 → Phase 3 J6 seam. `'policy_error'` remains a distinct string from `THUMB_ERROR_BROWSER_UNAVAILABLE` (`app.py:71`, raised only at the browser launch/new_page sites), so a refused target still reads as a per-service condition and never as a J6 machinery fault — preserving what CR-01/03-20-PLAN.md established.
